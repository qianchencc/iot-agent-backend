# 配置与数据治理规范

生效范围：新增／修改配置、存储、启动入口、控制台及相关验证。依据 [ADR0006](adr/0006-admin-configuration-and-user-audit-governance.md)。这是已确定的目标规范，不表示现有代码已经合规；逐项差距见[盘点入口](../.scratch/admin-console-governance/README.md)。

## 1. 三种权威来源

| 分类 | 权威来源 | 控制台 | 生效规则 |
|---|---|---|---|
| 程序默认值 | 版本化的非敏感默认配置 | 显示有效值与来源 | 不覆盖已有业务修订 |
| 部署启动配置 | 显式指定的外置 YAML，必要时引用权限受限的 secret 文件；平台可直接注入环境变量 | 脱敏只读、显示来源与变更影响 | 启动／受控重启；安全根不由控制台写入 |
| 可管理业务配置 | Java 管理的 MySQL 配置修订 | 具备真实消费链路的字段可编辑 | 保存、应用、采用版本分别可观测 |

不使用 `.env`，包括本地开发、shell source、Node dotenv 和 Compose 隐式发现。尚未切换的现有实例和历史 runbook 不因此自动迁移；不得在其他线程运行中更改其凭据、端口或数据卷。正式切换必须一次迁移全部启动调用方，去掉旧入口，保留带时间和来源的历史证据。

优先级按分类决定，而不是全局“环境变量永远覆盖”：部署参数允许显式平台覆盖；首次有效业务修订建立后，运行业务参数以 MySQL 为权威。启动文件中的模型等初始值不得永久锁死控制台。缺少关键安全根时 fail closed，不能以弱默认或旧快照掩盖。

## 2. 每个配置项的登记契约

新增项先分类，再实现；完成标准是定义、校验、消费、可观测生效、必要迁移和文档同一变更交付。

每项必须有：稳定键名、中文名称／描述、类型、单位、默认或必填、合法范围／枚举／跨字段约束、权威来源、秘密等级、作用域、实际消费者、加载时机、应用方式、失败行为、控制台位置、验证证据、废弃迁移方式。

- Spring 配置采用规范小写点分／kebab-case 路径；管理 API 字段可以是现有 camelCase，但两者必须显式一对一登记。只有一个校验和默认值定义，消费者不再各自兜底出不同语义。
- 实施统一设置入口与字段描述，不继续在业务逻辑分散新增 `@Value`、`Environment.getProperty`、`System.getenv` 或 Node `process.env`。既有入口先按盘点表迁移，不能只换文档中的名称。
- 密码／密钥、含凭据的 URL、桥接 Token、任务凭据、游标 HMAC 根均属于秘密；日志、变更历史和前端响应只保留存在状态或字段名。密钥轮换必须说明旧密文、会话和在途操作的影响。
- 密钥“留空不改、显式替换、显式清空”使用独立操作语义；必需密钥不允许清空，可选集成清空须同时满足禁用规则。当前 PATCH 直接收值的协议不等于该契约已实现。
- 超时、容量、并发和缓存策略可纳管，但须保留上下游 deadline、完整数据范围与授权新鲜度约束。不能把加密参数、幂等约束、设备温度边界、日界时区或协议格式做成任意输入控件。
- `fixture`、关闭身份验证、模拟成功等开发控制仅限隔离测试，生产控制台不提供这些开关。

## 3. 保存、应用与运行快照

定义清楚四种状态：编辑草稿、已持久保存、目标应用修订、消费者实际采用修订。

1. 保存由后端校验整个有效配置，使用 expectedRevision 防止覆盖；原子提交新修订。失败不得发布未提交配置。
2. 应用记录目标版本、影响字段／消费者和是否重启；在途工作阻塞时给出原因，不强行重启设备操作。
3. 按新运行生效的字段一次性捕获完整快照。该次运行的模型、指引、预算和审计关联版本不随中途保存变化。
4. 客户端重建／重启只在实际消费者接受目标配置后确认成功。supervisor 的 accepted 只代表已调度；无法确认时显示待确认或失败，不报全局已生效。
5. 混合版本如实显示具体字段和消费者差异；一个 activeRevision 不能冒充 Java、Node及所有组件都确认的证明。
6. 回滚生成新的修订及应用操作，不覆盖旧历史。密钥只显示是否替换，不展示历史值；不能把旧备份的加密根当普通可回滚字段。

现有 live 字段在保存后自动被下一轮采用、其他字段仍启动绑定。设计落地必须显式解决“保存”和“保存并应用”的语义，不能仅给现有 PATCH 再加一个按钮。当前默认 AdminWorkState 永远不忙、受监督应用无完成回执等差距列为交付门禁。

## 4. Java 与 Node 的配置边界

Java 拥有业务定义、授权、事实库及 Pi Session（ADR0004/0005）。普通公司、办公室及任务检查点都应获得完整、带版本的 Java 运行配置；Node 仅验证通用执行契约，不保留可悄悄覆盖 Java 的业务模型默认。

Node 启动配置仅含监听、Java 回调、私有认证、引擎通用资源和确有需要的观测传输；不传数据库、Redis、管理员或配置加密主密钥。桥接方向和凭据必须显式配对，不能假定 `agent.bridge.token` 与 `agent.bridge-token` 是同一 Spring 键。

Langfuse 不是业务审计。若由控制台管理，其 enable、连接及凭据必须真实传达到 Node 并确认采用；尚未接通时显示未接通，不允许保存即宣称启用。其可能包含请求／工具内容，必须独立治理。

## 5. 持久化记录的统一要求

每张表／JSON 事实登记：权威归属、主键和业务唯一键、tenant／身份域／稳定主体／source 的获取和校验方式、写者／读者、幂等与版本、敏感字段、追加／更新／删除语义、保留／归档／恢复方式、可用于控制台的投影。

- MySQL 保存业务事实与 Pi Session；Redis 仅保存可重建读能力及协调。管理界面通过 Java 模块入口和受控查询，不直接浏览任意表／SQL。
- 用户层级基于服务端核验的 `(tenant, identity realm, principal)`；ownerKey 是稳定隔离键但不可逆，不能作为姓名或声称已存在成员通讯录。公司/办公室是来源，不等于企业 ID。
- 外部对象关联先校验归属；只有 tenant 或设备目录可见不能代替操作授权。审计查询及导出也必须验证管理范围。
- 用户请求和最终答复可包含业务敏感信息；控制台按审计目的最小化展示。Pi 隐藏思维、完整工具原始内容、Token、密文和凭据哈希不进入普通成员轨迹页面。
- 新审计采用只追加、事件 ID 幂等、明确 actor/发起人/确认人/执行主体/对象/时间/结果/来源/关联版本；重复事件内容冲突不能覆盖原证据。查询、拒绝、确认与自动执行有不同事件语义。
- 既有 conversation_events 可因末轮撤回被删除，audit_events 可 upsert；不能把它们直接标成不可篡改审计。保留期、法定防篡改和导出要求尚需用户定案。
- 状态窗口、逻辑删除、到期不等于物理删除；不得未经批准删除事实或清空在线库。备份覆盖配置修订、业务事实、Pi 表及迁移标记，恢复先进入独立库。
- SQL 资源与 Java 初始化 DDL 的定义、旧库增量升级必须一致；有 CREATE IF NOT EXISTS 不代表历史库已迁移。按根规范保留 bigint unsigned id 与审计时间，已有主键差异明确登记并另行迁移。
- 当前结构入口为 `schema.SchemaMigrations`，由共享事实、任务生命周期、候选集和 Pi Session 初始化调用；`db/mysql/*.sql` 是列定义、注释及新库结构的唯一权威，旧库补列／换主键／注释收敛由该模块执行并登记。业务模块不得再新增独立建表或升级常量。原自然／复合唯一键须在移除旧主键之前建立，避免中断窗口丢失幂等约束。
- 候选集旧句柄从原 JSON 回填，重复或格式非法的非空句柄明确失败，不任意改写历史引用；没有短句柄的旧记录保留 null 和原完整 ID，不臆造 `sN`。新记录每会话通过持久序号行在同一事务中分配短句柄并与事实一起提交。新增序号表也遵守规范主键、审计时间与逐列注释。
- 审计列回填须说明来源：迁移登记沿用 `applied_at`，恢复检查点缺失的创建时间沿用原 `update_time`，屏障缺失的 `issued_at` 沿用原 `update_time`。这不证明原业务发生时刻，不用启动时刻伪造历史。补列、回填与收紧非空分别自守卫，重启可继续未完成步骤。
- 已验证的新库及旧结构夹具包含33表，保留 Pi 租约／版本／提交回执、任务补投事实、旧会话迁移标记和候选集引用；见[技术规范改进验证](../.scratch/technical-spec-compliance/evidence/result.json)。2026-11-05 已对本地固定业务库执行升级：先备份到私有发布目录、在独立库恢复预演，再在无在途运行时切换；原记录数量、配置密文、候选集 JSON 与 Pi fencing 事实均保持，59 条无短句柄旧候选集保留完整 ID。见[固定实例升级证据](../.scratch/technical-spec-compliance/evidence/fixed-latest-20261105.json)。其他实例首次采用仍须独立备份及升级窗口；换主键可能重建表，程序回退不能代替数据恢复。

## 6. 证据与完成门禁

盘点：至少覆盖配置声明、条件 Bean、计划任务、环境读取、实际消费者及 SQL／Java DDL；第三方隐式参数与任意数值常量不能伪称全量审计。只读库检查限定本地允许 schema，导出元数据和聚合数量，不导出用户正文／凭据。

实施：复用公开配置／HTTP／存储入口验证秘密不回读、版本冲突、提交失败、在途旧快照、新运行新快照、重启未完成、未知控制结果及恢复语义；运行真实隔离程序检查改变的路径。控制台必须用浏览器检查加载／空／错误／冲突／窄屏和键盘状态，类型检查不替代视觉证据。

本节原始治理盘点未修改运行实现、切换 `.env` 或重启业务服务；后续实现及本地固定实例升级以第5节所链证据为准，不能仅因规范文件更新而标记差距已修复。
