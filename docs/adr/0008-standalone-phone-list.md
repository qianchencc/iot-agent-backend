# 手机号白名单与公司任务功能

Status: accepted · Updated: 2026-11-11 · Supersedes: ADR0007

## 2026-11-11：仅开放名单内用户的公司任务功能

复用现有手机号名单：按后端已核验的 `mobileNumber` 匹配，决定公司仪表盘任务中心与公司 Agent 任务能力。不限制普通公司查询，不改变办公室功能、设备授权、调度或已确认任务；移除名单不自动取消已有任务／周期计划。

MySQL 为持久来源；单实例启动读取一次，管理事务提交后发布不可变内存集合，回滚不发布。普通业务只做内存匹配，不逐请求查库、不新增上游核验、轮询、Redis或权限表。当前要求管理修改通过同一实例的管理入口；直接改库或多实例同步不在本轮范围。

`GET /api/agent/company-task-access` 只返回当前账号的 `enabled`。前端进页／换身份读取，不轮询；仪表盘结果共享给公司浮层，未开放时隐藏任务入口、任务卡和引导，不预取／轮询公司任务。通知中心保留独立入口。后端在任务HTTP入口和统一工具分派入口校验最新集合，任务工具列表按资格生成，旧确认卡与旧运行不能绕过。

验证与真实界面边界见[本轮证据](../../../mp/.scratch/company-task-access/evidence/TASK-ACCESS-01/result.json)。

## 2026-11-11：姓名仅关联本地业务记录

添加白名单只接收手机号，不接受手工姓名或备注。列表及添加响应中的 `name` 仅按手机号关联已有可信公司／办公室业务事件中的 `displayName`，要求同一事件具备已核验主体和身份域；不使用历史手工备注、操作者姓名或其他猜测作为回退。同一手机号出现不同姓名时不自行选取。

暂无姓名或姓名元数据读取失败不影响提前加白、名单持久化与任务资格；后续存在对应记录后，重新读取名单自动显示。生产实现每次管理读取使用一次批量本地查询，不逐人查询、不访问上游、不增加同步作业；普通业务的任务资格内存匹配保持不变。旧 `phone_allowlist.name` 列及数据保留但不再读写，不实施数据清理。

定向回归、隔离 MySQL 验证与本地真实控制台截图见[本轮证据](../../.scratch/allowlist-auto-name/evidence/NAME-01/result.json)。


## 历史决定：2026-11-04暂不接入业务

用户明确纠正：白名单暂时不接入实际业务，其作用也不是控制谁能使用公司Agent。本轮仅提供管理员维护手机号与可选姓名备注的持久化名单，添加、移除、空名单及名单故障均不影响公司或办公室Agent、原有身份认证、设备权限、任务及周期计划；不实现准入匹配或任务取消，不新增官方账号目录或要求用户先登录。

名单维护与成员业务轨迹是两件事。审计成员来自已有可信业务身份和业务事件，不以白名单作为成员目录或读取前置，不把名单备注说成官方姓名。名单管理操作可以记录管理员变更事件，但不能制造“已开通Agent权限”“已取消任务”等假结果。

这一决定撤回ADR0007的业务绑定，不对名单未来用途作推断。用户已同意其余控制台范围并要求继续实施：独立管理员登录、真实运行配置管理、按用户组织的公司／办公室操作审计；范围与验证入口见[规格](../../.scratch/admin-console-governance/spec.md)。
