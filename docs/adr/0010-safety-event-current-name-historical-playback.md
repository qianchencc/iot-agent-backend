# 0010：告警原事件与当前设备资料分离

日期：2026-11-11。状态：已采纳并实施；前端验证范围见文末。

## 问题与证据

同一硬件的原告警名称记为27楼，设备当前资料记为26楼，两者并不冲突。问题是程序把事件名称与当前设备名称混成一个字段，并按当前位置替历史事件找监控；中途又误把缺少预存摄像头关系当作禁止查询的理由。

告警事实来自既有后台同步的上游记录，不由模型生成。同步入口、事件落库与当前运行包已核对；原事件ID、设备身份、记录时间、报警标记不因展示改名重写。

## 用户确认的行为

1. `deviceName/recordedDeviceName`保留上游告警事件名称，不由当前设备名覆盖；告警ID、设备业务ID、记录时间及报警事实不改写。
2. `currentDevice.name/location`使用后端完整目录的当前设备资料。先检查安全授权，再按同实例、同租户、硬件ID关联；不改变授权和控制绑定。旧告警的当前设备资料同样随目录更新，但不重写旧事件内容。
3. 监控查询使用原告警记录的名称／地点线索，在当前视频授权内找候选；不能把当前设备名称、位置当成原事件内容。回放固定原告警时间前后各15分钟，不取当前时间、同步时间或迁移后的设备位置作为替代。
4. 基于原事件名称检索的是监控候选，不等于补造了已核实的历史摄像头关联；不新增历史快照或设备迁移系统。
5. 没有预存摄像头关系、没有当前设备状态，均不能直接封死监控查找。只有原记录没有可用线索、或当前视频权限内没有匹配时，才如实返回未找到候选；不否定原始告警的真实性。
6. 前端、HTTP、Agent及核验只消费后端本地数据；交互和缓存缺失不访问客户上游。仅既定后台同步采集数据，监控实际播放沿现有动作出口。

## 最小实施范围

- 复用完整目录存储补齐台账当前设备信息；原事件名称和当前设备名称分开呈现，不覆盖原始记录。
- 恢复现有监控候选／回放入口，把候选检索输入从当前设备位置改为原告警记录，保留原事件时间及视频权限检查。
- 撤销无条件返回“无法自动定位”的错误前置限制；不新增缓存、调度器、历史关联表或通用位置历史系统。
- 原有授权、控制绑定、告警记录身份和数量不变。已发布报告的独立证据快照不重写。

## 本轮能力核对与实施取舍

既有定时后台同步观察到的烟感响应字段为`id/createdAt/modifiedAt/createdBy/modifiedBy/version/isDelete/deviceId/deviceName/elementId/elementName/alarm/report`。当前转换保留事件ID、设备ID、原名称、`createdAt`对应的告警时间、`alarm/report`，不保存完整原始响应。`elementId/elementName`的业务含义未核实，不解释为摄像头绑定。原事件名称中的地点用于检索监控，不要求额外历史快照。

当前设备信息每次台账读取从已授权设备的硬件ID集合批量读取本地完整目录；事件名称仍来自原记录。前端标题显示原事件，当前设备名称不同时独立标为“当前设备”，位置独立标为“当前位置”，不能把26楼当前位置拼成27楼原事件的一部分。

## 验证接口与标准

沿既有公开接口`DeviceDirectory.safetyHistory()`、`ObservationAdapterFactory.composed()`及安全台账HTTP验证：事件原名不被当前名覆盖，当前资料能动态更新且不扩大权限；原事件写10楼、当前设备移到20楼时仍查10楼候选；没有当前资料仍可按事件查监控；回放窗口保持原告警时间，普通读取上游调用为零。

真实开发者工具已核对用户2026-10-16 11:12燃气事件：标题27楼茶水间、当前设备26楼未来智城、返回1路27楼茶水间监控，回放表单默认同日10:57—11:27。前端移除重复“台账来源”，读取时间标为“本次读取”，不表示告警时间或同步时间。证据位于小程序`.scratch/safety-event-identity/evidence/SAFETY-IDENTITY-01/`。未点击实际取流、未触发报警、未下发控制，不以表单通过冒充录像可播放验收。
