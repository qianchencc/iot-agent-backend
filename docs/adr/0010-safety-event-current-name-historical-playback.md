# 0010：告警统一采用智慧消防资料

日期：2026-11-12。状态：已采纳；替代2026-11-11使用物联网引擎补齐当前资料的方案。

## 事实与决定

智慧消防与物联网引擎分别维护设备资料。2026-11-12实测，智慧消防改名后，同一设备的旧告警名称也变更：已同步的40条烟感事件均返回26楼新名称，包含昨天曾返回27楼的同一事件ID。智慧消防安装地址仍为27楼旧值；名称和地址不能假定自动一致。

1. 告警`deviceName/recordedDeviceName`使用智慧消防告警接口本次同步返回的名称；不是不可变的事发名称快照。上游变化后，本地按原同步规则更新，不用设备目录主动覆盖事件名称。
2. `currentDevice.name/location`及顶层`location`只取已授权的智慧消防设备目录名称和安装地址。保留租户／主体范围，取消本地完整物联网目录的资料关联，不增加回源或额外授权。
3. 列表和详情展示事件接口名称；名称不同时另列“当前设备”，位置标为“当前位置”，其含义是智慧消防当前安装地址，不能称为事发位置。事件ID、设备业务ID、时间和报警标记保持来源值。
4. 现有监控查询仍按告警响应名称的地点线索在视频权限内找候选，回放使用事件时间前后15分钟。上游历史名称会变化，因此候选不是可靠的事发位置证明；本轮不改匹配算法，不新增自动判断、位置快照或数据补造。摄像头资料继续来自视频目录，不属于消防目录。
5. 前端、HTTP、Agent和设备核验只读后端本地已同步数据。后台同步及既有视频播放出口保持原边界；资料缺失不回退物联网引擎。

## 来源字段

告警响应已观察字段：`id/createdAt/modifiedAt/createdBy/modifiedBy/version/isDelete/deviceId/deviceName/elementId/elementName/alarm/report`。

当前转换保留事件ID、设备ID、名称、`createdAt`对应时间、`alarm/report`，不保存完整原始响应。`elementId/elementName`不能未经契约确认当作精确事发位置或摄像头绑定。`observedAt`是本端本次读取时间，不是同步或告警时间。

## 验证边界

沿`DeviceDirectory.safetyHistory()`验证：消防资料与物联网引擎冲突时采用消防资料；消防资料更新后列表、详情、最新记录一致；事件身份／时间保持；租户隔离、不扩大设备授权、普通读取不回源。真实小程序验证三类台账展示消防安装地址，不改上游资料、不触发报警、不取流。

2026-11-11的截图保留为历史证据，其“当前资料26楼取自物联网引擎”和“原名称不会变化”的推断不再作为现行验收结论。
