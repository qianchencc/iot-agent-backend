# 0010：告警当前名称与事发取证依据分离

日期：2026-11-11。状态：用户已确认，实施中。

## 问题与证据

同一硬件的完整设备目录已显示当前名称、位置，安全业务授权资料与新告警附带名称仍可保留旧值。现有台账用安全授权资料生成 `currentDevice`，监控候选又按当前位置或名称解析出的楼层匹配，混淆当前展示资料与历史取证依据。

告警事实来自既有后台同步的上游记录，不由模型生成。同步入口、事件落库与当前运行包已核对；原事件ID、设备身份、记录时间、报警标记不因展示改名重写。

## 用户确认的行为

1. 所有新旧告警的标题使用后端完整目录的当前设备名称；当前位置同源。先检查安全授权，再按同实例、同租户、硬件ID关联展示资料；完整目录不授予额外权限。
2. 事件身份、原始记录名称、时间和报警事实保留；不清库、不重建记录，不以当前资料覆盖历史事实。
3. 监控关联使用事发时有来源依据的位置或摄像头关系，回放使用该事件原始时间。改名、搬迁不能使旧告警重新匹配到当前地点的摄像头；当前视频授权仍须检查。
4. 名称里的楼层不是独立位置证据。首次打开或首次同步旧事件时的当前位置不能伪装为事发快照。
5. 后台同步能取得的事发关联应保留供读取；确实没有历史依据时，明确无法自动定位，不假装没有摄像头，不按当前资料或旧名称猜测。
6. 前端、HTTP、Agent及核验只消费后端本地数据；交互和缓存缺失不访问客户上游。仅既定后台同步采集数据，监控实际播放沿现有动作出口。

## 最小实施范围

- 复用完整目录存储补齐台账当前设备信息；统一列表、最新、详情、摘要、Agent及监控入口中的当前资料。
- 核对后台同步实际可取得的历史字段，再确定必要持久字段；不发现场诊断请求、不臆造上游字段或事发关系。
- 去掉按当前位置／名称猜历史监控的路径，保留原事件时间及回放窗口，不新增缓存、调度器或通用位置历史系统。
- 原有授权、控制绑定、告警记录身份和数量不变。已发布报告的独立证据快照不重写。

## 验证接口与标准

沿既有公开接口 `DeviceDirectory.safetyHistory()`、`ObservationAdapterFactory.composed()` 及安全台账HTTP验证：当前名称更新而旧记录事实不变、当前目录不能扩大安全权限、历史监控不随当前资料变化、缺依据不误配、回放窗口保持原事件时间，普通读取上游调用为零。

使用真实开发者工具复验当前账号的新旧告警标题、详情与监控缺依据状态；工程测试和HTTP检查不替代界面验收。不得为验收触发真实报警、控制设备或创建任务。
