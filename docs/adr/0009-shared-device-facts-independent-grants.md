# 0009 — 共享设备事实，独立用户授权

- 状态：Accepted
- 日期：2026-11-10

## 问题

当前观测与环境历史按采集账号保存；新账号即使拥有相同设备权限，也会等待重复采集。事实所有权与用户授权混在一起，增加等待与来源负载。电表历史已有跨账号读取，但同集合的当前采集／失败等待仍可能重复。

## 决定

- 使用现有 MySQL 和后台同步；不新增服务、队列、缓存层或用户级预热。
- 事实与授权分开。当前观测共享域为网关实例、租户、company／office 来源；设备键包含类型、来源 ID 和实际采集定位／绑定。名称不改变物理身份。
- 读取先取得本人的已发布本地授权，再读取共享事实，返回前重验授权代次与设备绑定。凭据轮换先重建本人授权；不能借其他人的权限，也不要求重采相同物理事实。
- 当前采集按设备领取到期任务，仅调用未覆盖／到期的设备；同权限账号增加不重复采样。既有主体调度间隔仍保留，DISPATCHED 游标只有派发时间、没有成功时间，不参与事实新鲜度。
- 环境历史在同来源域、完全相同的授权物理测点集合内共享进度和样本。原始 deviceCode 仍无已证明的设备／楼层关联，不能推导归属或混用不同集合。既有站点历史语义不变。
- 电表历史沿用既有共享样本／覆盖模型，不重写原始数据；同电表集合复用成功覆盖与失败等待，首次无覆盖时只做全量，不并行重复一次当前流。
- 后台发布仍受采集者当前凭据代次／目录版本和采集尝试 CAS 约束。失败保留旧值；迟到样本不覆盖更新值，采样未知仍为 null。
- 同步成功、尝试、来源采样及用户派发是不同时间；新增查看者或投影重建不能更新事实时间。
- 前端、HTTP、Agent、报告、任务核验只读后端本地事实。来源读取只由既定后台同步／监控执行；真实控制下发不在本次变更范围。

## 迁移与保留

`SchemaMigrations.ensureLocalCompanyDirectory()` 登记 `local-shared-observations-v2`，在同一事务中合并旧当前观测、环境样本／进度／请求，并登记完成；失败连同登记回滚，重复启动不重复迁移。状态列注释由既有 polish 机制登记独立版本收敛。

只把同步时间不早于当前目录发布的旧观测迁到对应物理绑定；无法证明的原行保留但不作为新绑定事实。环境历史按同集合合并，保留原始值、精度、采样、同步及覆盖时间；电表原始历史不改写。

共享事实不属于采集账号，不随用户清理删除。电表既有来源索引仍引用 local_sync_scopes，清理用户时必须保留其事实来源元数据，不能级联删除历史或来源索引。

切换前停旧实例，保存受影响事实表、进度、请求及 storage_migrations 的一致私有备份；回滚须停新实例、恢复对应表／本迁移登记、再启动旧包，禁止仅回退二进制。备份不入 Git；其他业务及并行修复不随本次恢复覆盖。

## 取舍

- 用户自身权限仍有账号维度的后台准备成本；本次消除设备数据的重复采集，不承诺所有新账号授权零等待。
- 不同环境测点集合不强行共享站点历史；无可证明的本地覆盖时明确准备中，不伪造空值或现场补拉。
- 清理采集者不会删除新的共享当前观测／环境历史；电表保留既有来源索引约束。

## 验证

- 完整 Java 回归：755 项，726 通过、29 跳过、0 失败／错误；已知无关回放失败方法 `SafetyReviewToolContractTest#singleCandidatePreparesRealPlaybackCardAndProjectsVideoPlaybackBlock` 显式排除。
- 隔离真实 MySQL、合成来源：100 个同权限新账号读取原有环境当前值与历史，当前采集 1 次、历史全量 1 次，原始时间及小数未变化。迁移故障事务回滚、重复初始化、采集者退役、断源重启后读取均通过。
- 隔离真实 MySQL 电表：两个同权限账号初次全量 1 次；来源失败时当前流只尝试 1 次，保留原样本并标陈旧。
- 行为回归覆盖不同租户／来源／网关／绑定、独立授权、撤权、凭据轮换、未覆盖设备与慢全量／新当前竞争。
- 烟测使用非池化 DriverManagerDataSource，串行批次仅证明数据与采集次数，不作为真实延迟或公司容量承诺。未用客户上游做诊断。
- 新账号微信首入业务验收仍须真实账号界面证据；工程结果不替代该验收。
