# 0006 — 控制台统一配置治理与按用户归属的审计

Status: accepted（方向与边界）；实现尚未切换 · Date: 2026-11-03

控制台保留在本仓库 `web/admin/`，采用 Vue 3 / TypeScript / Vite / Element Plus；用户已选择原型 A「成员分栏」，公司 Agent 与办公室 Agent 的业务轨迹统一按用户归属组织。保留园区、身份域和 Agent 来源作为范围维度，不把 `source=company` 或园区码冒充企业成员关系。独立的单管理员身份由部署配置提供凭据，不建立客户成员登录或多管理员体系；共享凭据只能归因至该管理员账号，不能证明具体自然人。

不再使用 `.env`，包括本地开发。采用程序内非敏感默认值、显式路径的外置 YAML 启动配置和 MySQL 中版本化的可管理业务配置。允许部署平台直接注入环境变量，但不以 dotenv、shell source 或 Compose 隐式加载 `.env` 作为运行流程。配置加密主密钥、事实库连接和管理员凭据属于部署根，不由控制台修改；业务配置首次初始化后以 MySQL 为权威。Node 不获得数据库、Redis或管理员凭据，继续遵守 ADR0004/0005。

保存和应用必须有可核验的不同含义：持久化提交不等于所有消费者已采用；新运行使用完整、不可变的配置快照，在途运行继续旧快照。必要时允许受控重启，但不得强制打断在途设备执行。以消费者确认和目标版本实际可用作为应用成功证据，supervisor 接受重启只算已调度。当前存在 live 字段随保存自动进入下一轮的机制、启动绑定参数和未接通字段；本决策不宣称已完成统一生效机制。

## 取舍与执行入口

- 不让控制台重写 YAML 或 `.env`；避免多实例文件分歧和不可追溯修改。
- 不将所有常量都变成参数；协议、授权和设备安全不变量仍由代码与领域契约保证。
- 不直接把含虚构身份和假成功的视觉原型提升为生产实现；保留原型分支作为信息层级证据，正式界面重用真实 API 与错误语义。
- 规范：[配置与数据治理](../configuration-governance.md)。逐项盘点、真实本地数据库元数据和控制台设计入口：[工作记录](../../.scratch/admin-console-governance/README.md)。
