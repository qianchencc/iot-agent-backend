# 用户分层控制台与配置治理规格

Status: approved-for-implementation（2026-11-04用户批准继续实施；**白名单仅维护手机号与备注，不接业务，不控制公司Agent资格、不取消任务**，见[ADR0008](../../docs/adr/0008-standalone-phone-list.md)；其余配置与用户审计范围不变）

## Problem Statement

管理员需要独立维护手机号名单、调整实际运行参数，并按用户查看公司／办公室操作记录。白名单与用户审计API尚不完整，配置定义与实际消费者需统一；沿用工作区已有Element Plus迁移继续完成，不回退已有成果。

## Solution

在现有 `web/admin/` 内完成Vue3 / Element Plus控制台。保留A「成员分栏」作为审计页面结构，但只交付白名单、参数配置和用户操作审计三项能力，以及独立管理员登录。Java继续拥有业务身份、授权和事实，Node只提供通用Agent引擎。

## User Stories

1. 作为管理员，我希望以部署管理的独立凭据登录，以便与业务成员身份分离。
2. 作为管理员，我希望在缺少配置时明确知道原因，以便安全完成首次业务配置而非使用默认密码。
3. 作为管理员，我希望按成员查找，以便追踪公司和办公室两种来源下的行为。
4. 作为管理员，我希望直接登记手机号与可选姓名备注，不必查询官方用户目录、等待用户登录或填写园区、身份域和内部用户ID。
5. 作为管理员，我希望清楚知道名单尚未接入业务，添加或移除不改变公司Agent资格、设备权限及任务状态。
6. 作为管理员，我希望名单编辑可取消且保存有版本校验，以便避免误修改和并发覆盖。
7. 作为管理员，我希望名单添加与移除留痕，以便知道管理员何时更改过什么记录。
8. 作为管理员，我希望查看成员原始业务请求与对外答复，以便满足审计目的。
9. 作为管理员，我希望把模型建议、人工确认、上游受理和状态回读分别查看，以便不把建议误当执行。
10. 作为管理员，我希望看到拒绝、失败、部分结果和未知结果，以便审计不只记录成功。
11. 作为管理员，我希望区分任务创建者、确认者和系统执行者，以便自动执行正确归因。
12. 作为管理员，我希望按成员／来源／期间／类型／结果分页检索，以便可控地查阅历史。
13. 作为管理员，我希望查看关联草案、任务和报告的只读事实，以便理解事件来源。
14. 作为管理员，我希望业务审计独立于Langfuse，以便观测关闭不丢失审计要求。
15. 作为管理员，我希望按职责分组修改模型、指引、运行预算、物联和观测参数，以便无需寻找分散的启动变量。
16. 作为管理员，我希望每项注明单位、边界、来源、作用域和生效方式，以便知道改动影响。
17. 作为管理员，我希望秘密只可替换且历史不回显，以便避免泄露现有凭据。
18. 作为管理员，我希望跨配置页保留草稿，冲突时不丢修改，以便安全完成复杂编辑。
19. 作为管理员，我希望连接检查使用草稿且不自动保存，以便先验证候选配置。
20. 作为管理员，我希望分别知道保存修订、目标应用和实际采用，以便不被假成功误导。
21. 作为管理员，我希望在途工作不被应用操作强制打断，以便设备执行与任务事实保持可解释。
22. 作为管理员，我希望恢复旧配置生成新修订，以便变更过程可追溯。
23. 作为管理员，我希望部署根只读且说明运维入口，以便不把事实库或加密根改坏。
24. 作为管理员，我希望查看Java/MySQL会话健康和一致恢复范围，以便正确维护Pi Session而非操作旧Node文件。
25. 作为运维，我希望所有环境使用明确配置文件启动而不依赖.env，以便交付过程一致。
26. 作为使用者，我希望键盘、窄屏、加载、空态和错误都有完整反馈，以便控制台可实际操作。

## Implementation Decisions

- 本轮只交付三项能力：用户白名单、后端参数配置、用户操作审计；配置和审计需要独立管理员登录。
- 白名单本轮仅维护手机号及可选姓名备注，不接入任何实际业务；不是公司Agent准入规则，不新增认证、目录查询或先登录前置。不因添加、移除、空名单或存储故障改变公司／办公室Agent、设备权限、任务或周期计划；不进行任务取消。后续用途需另行明确，不沿用已撤回的准入／取消解释。
- 审计按用户组织company和office来源，回答谁、何时、做了什么、结果如何；不展示Pi隐藏思维、密文或无关原始工具响应。
- 沿用Java业务事实和公开模块入口、Node通用引擎、Java/MySQL Pi持久化；不建立第二套身份登录系统或Node数据库连接。
- 白名单与成员业务轨迹独立。成员轨迹仍由原有可信tenant、identity realm、principal及ownerKey归属；不根据白名单伪造已核验用户，不修改业务身份读取流程，也不为本轮名单新增mobileNumber匹配调用。
- 管理员为单一部署身份，凭据不由Web修改；共享凭据的自然人归因限制明确。
- 配置来源统一为程序默认、外置YAML部署根、MySQL可管理业务修订；`.env`加载退出。每个可管理字段集中定义描述、验证、消费和应用元数据。
- 保存、目标应用和消费者确认分别显示。新运行采用新配置，在途运行保留旧快照；未接通字段不显示为可用控件。
- 审计写入为明确业务事件；幂等重复不覆盖原内容；读取验证管理范围；秘密不回显。
- 使用Element Plus和集中主题；组件只覆盖真实页面状态，不复制原型模拟成功逻辑。
## Testing Decisions

已按用户“其余基本同意，尽快完成推进”采用管理HTTP＋真实配置消费者＋隔离MySQL作为共享工程验证接缝，浏览器验证管理员可见行为；小程序业务仍以真实界面操作结果验收，不以getter单测或HTTP成功替代。

- 复用现有Admin配置契约、Business Agent Definition、私有桥接认证、存储集成和Pi一致性接缝；正式新测试只覆盖用户可见的边界、状态转换及失败。
- 验证缺配置fail closed、秘密不回读、初次配置、错误校验、expectedRevision冲突、事务失败不发布、已有运行保持旧快照、新运行采用新快照。
- 验证应用受阻／组件未确认／重启失败不报成功；恢复创建新修订。验证Java与Node实际运行参数，不只比较转发副本。
- 两个可信隔离身份验证成员、来源、归属和授权；普通成员绕过前端直调仍被后端拦截。只读上游或隔离设备协议夹具，不控制真实设备来证明拒绝。
- 白名单验证手机号格式、备注、重复、空名单、添加／移除、持久化、expectedRevision冲突与管理审计；不以官方账号搜索或已登录成员存在作为录入前置。
- 名单操作不得调用业务准入、身份认证、设备控制、任务取消或调度接口；独立名单页面明确未接业务。公司／办公室原有登录及业务权限不变，不使用名单故障制造业务拒绝。
- 审计验证查询/拒绝/建议/确认/结果未知和自动执行主体、幂等冲突、不因清会话删除、脱敏与管理范围；导出若纳入则单独验证过滤及注入边界。
- 浏览器真实走登录→成员→两来源轨迹→授权草稿取消/保存→配置修改/冲突/应用→历史；320px、200%缩放、键盘、抽屉关闭和焦点恢复、加载/空/错误状态均检查。
- 实施及隔离验证已执行，当前结果见[收口票据](issues/05-console-acceptance.md)。历史只读盘点与当前实施证据分开记录；未做生产配置切换或真实控制／任务／通知验收。

## Out of Scope

- React/Vben迁移、多管理员／SSO平台重建、任意SQL浏览器。
- 默认允许管理员直接下发设备、接管他人任务或绕过上游设备授权。
- Node直连数据库、本地SQLite／会话卷、旧会话导入、以Redis替代事实库。
- 将所有常量变成任意控制台参数；将隐藏思维或原始凭据放进审计。
- 本轮在独立本地验证环境中实施与验证；不切生产、不下发真实设备指令、不创建生产任务、不发送通知，不删除用户既有数据。
