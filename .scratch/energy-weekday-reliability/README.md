# 能耗复用与工作日计划可靠性修复

日期：2026-11-09。范围：本地 Java 3381；不修改云端生产 Runtime、Node、模型、计划定义或前端展示逻辑。全程由主代理实施，无子代理。

## 最小方案

1. `EnergyHistory` 保持当前用户专用电表授权与读取前后重验。原始采样和完整覆盖按同网关、同租户、同来源及已授权电表复用；相同来源记录读取最新已发布修订。使用既有表，不搬迁或复制历史、不删旧副本、不新建缓存。后台沿既有60秒现值更新和深夜完整校对：已有新鲜事实时不重复采样，已有本夜完整覆盖时不重复全量；真正未覆盖电表仍准备中。
2. `TaskProjectionStore.list` 展开窗口内所有合法发生日，而非每计划每窗口只留最近一条；`TaskDetailProjector` 使用 `TaskRecurrence` 校验工作日、周几、月日及截止日，并区分单次任务与计划预览，已物化任务不重复生成虚拟安排。
3. `TaskPlanStore` 保存单次覆盖及物化器推进时，都按覆盖实际时刻计算下一指针；宽限不再使用旧模板时刻。全部过期的阶段仍保存为 `MISSED`，不补发过去控制。已被旧代码遗留、仍有明确覆盖负载却没有任务事实的记录，仅补错过历史，不倒退未来指针；手动 `SKIPPED` 不改写。
4. `TaskExecutionIdentityStore` 的 MySQL `INSERT SELECT ... ON DUPLICATE KEY UPDATE` 使用 `VALUES(owner_id)` 消除列歧义，保持密文复制、解密和幂等；不绕过执行身份校验。

没有新增状态、队列、调度器、基础设施、配置键或数据库结构。
