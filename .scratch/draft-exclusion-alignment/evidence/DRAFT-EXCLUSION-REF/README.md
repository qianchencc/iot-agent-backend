# DRAFT-EXCLUSION-REF：排除短引用对齐

结论：**草案生成／取消已真实小程序验收；未确认设备执行。** 详细事件、产物哈希及失败记录见[result.json](result.json)，要求见[票据](../../issues/01-cross-set-device-exclusion.md)。

## 简单设计

- `dN_k`先补查当前对话的`sN`，复用租户、主体、来源、对话、目录指纹、精确范围及完整成员校验；排除设备仍须属于本次包含范围。
- 排除引用使用单独索引。来源集合不加入操作范围，也不授权它的短号作为`actions`目标。
- 顶层与`lighting`按**真实设备ID**取并集，再做最终成员校验。不是全局放宽重复输入规则。
- 数据库完整ID／短号查询均显式绑定`conversationId`；旧无上下文重载已移除。没有新重试框架、状态、系统提示词限制或通用引用平台。

## 失败与修复依据

1. 原用户两次合法`d8_*`／`d9_*`排除被当成未解析字面量；原Runtime `pi-runner.ts:717-725,759-760,879`会补查来源集合。
2. 隔离MySQL证实：不同对话同为`s8`时，旧全局“最新一条”查询会误拒绝旧对话；此项不是原截图失败的已证原因。
3. 真实UI又发现顶层＋照明同时排除同一短引用时，先合并字符串、后解析导致重复误拒绝。现先统一真实ID再取并集。

三项均保留公开提案入口的失败前／成功后回归。另一次真实状态读取失败如实留档，未增加自动重试或伪造状态。
