# 03: 用户授权目录与电表成员差量发布，保持权限及批次一致性

**What to build:** 用户的设备范围和电表专用授权正常刷新；成员及资料未变时不整批重建，撤权、换证和绑定变化仍准确生效，普通查询、草案与任务核验继续读取本人授权的本地数据。

**Blocked by:** None (can start immediately).
**Status:** completed
**Execution:** 已实现、公开入口回归及隔离真实MySQL验证；2026-11-12已部署固定Java3381。真实微信业务页未复验。

## 前因后果

系统把共享设备事实与独立用户授权分开。每位用户仍需建立并维护本人授权，不能因为其他人有相同设备就借用其权限。Company／Office目录和区域关系支撑设备检索、候选集、草案及任务核验；电表专用授权不能由完整展示目录推导。

当前用户目录成功发布会按scope删除重插设备、授权及位置／Office／区域关系，电表专用成员表也每轮删除重插。自然观察窗口内，用户设备、位置、授权关系分别贡献约0.538／0.287／0.204MiB行事件，电表成员约0.135MiB。关闭日志不消除这些数据库操作本身。

## 目前问题及关键约束

- 内容未变化仍重建正文及关系，产生重复数据库工作。
- 现有目录batch_version同时参与读取一致性、授权关联及在途状态发布，不能简单不递增版本或删掉版本检查。
- 电表grant_version在成员／凭据不变时本来就不变；优化应复用这项规则，而不是增加第二套授权模型。
- 部分版本元数据写入有必要。目标是避免正文重建，不是要求所有授权进度绝对零写。

## 改进目标与实施范围

1. 完整授权批次成功后，在原事务内对设备、位置路径、Office／区域关系及电表成员做批量差量比较；仅处理实际新增、变更和移除。
2. 比较覆盖来源身份、类型、资料、关系、实际控制／采集绑定和相关metadata，不能只比较成员ID或原始JSON字符串；保持既有顺序和固定候选成员语义。
3. 无变化正文不删除重插；同步成功、授权发布时间及必要批次围栏仍推进。若既有关系需要版本戳，可保留轻量元数据更新，不为零写强造版本模型。
4. 不改变batch_version对消费者的含义作为首选；确需调整时，在本票内迁完读取复核、候选集、状态采集及安全／能耗授权消费者，证明不会错误拒绝或接受旧结果。不留长期双轨接口。
5. 换证先重建本人授权，撤权立即拒绝相应范围；共享事实不因授权移除而删除。成功完整空授权和失败半批分别处理。
6. 复用现有模块、事务及公开入口，不新增通用差量框架。完整展示目录的正文发布归02，历史电表样本不在本票修改范围。

## 非目标

不减少权限检查，不跨账号共享授权，不强制合并历史物理样本，不改电表／环境的逐记录时间保护，不修改真实控制下发或已确认任务生命周期。

## 验收标准

- [x] 完全相同授权批次不重建设备／成员／关系正文，成功及必要版本信息有效；电表原有grant_version规则保持。
- [x] 单成员新增／移除、资料／路径／Office／区域变化、同ID绑定变化均准确发布；相同正文不重建。
- [x] 撤权、换证、跨账号、跨租户、Company／Office隔离回归通过；共享事实保留，未授权用户不能借用。
- [x] 完整空范围可发布；来源／校验／事务失败不发布半批，成功时间不伪造。
- [x] 慢状态采集、目录发布及读取交错时的原批次围栏和返回前授权复核保持。
- [x] 设备检索、固定候选、草案／过期核验、任务只读核验与能耗授权通过原公开入口回归；未执行真实控制或创建任务。
- [x] 隔离真实MySQL分别记录正文、关系与必要元数据操作，不以总行数不变宣称完成。
- [x] 普通读取来源调用增量为0；约60秒及完整历史策略保持，模块说明和执行证据已更新。

## 最终预期效果

用户看到的范围、资料和权限行为不变，后台减少相同授权批次的重复重建。保留必要版本写入，优化的是实际重复工作，不承诺零写入、所有新账号零等待或现有表文件立即缩小。
