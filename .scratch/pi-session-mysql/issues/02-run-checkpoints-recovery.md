# 02: 在途检查点、并发与中断可解释恢复

**What to build:** 真实模型对话遇到旧 writer、网络应答丢失或 Node 中断后，已提交上下文与工具事实不重复、不被覆盖；未保存的轮次不伪装成成功，用户可基于已知状态继续。

**Blocked by:** [01 新会话经 Java/MySQL 保存并完整重开](01-new-session-mysql-contract.md)

**Status:** ready-for-agent

**Execution:** not-started

规格：[统一 MySQL 会话持久化](../spec.md)。验收：[预期效果与验收](../acceptance.md)。工程通过不等于业务通过；不修改或关闭原业务恢复父票。

## Acceptance criteria

- [ ] 运行在调用工具前取得 Java 权威写入资格；旧实例的追加、工具回调及终结均被拒绝，不仅在整轮结束做 CAS。
- [ ] 完整消息和工具意图/结果形成持久检查点，不能只在整轮结束保存，也不逐 token 开数据库事务；事务不跨模型或上游调用长时间持有。
- [ ] 相同提交标识/相同内容返回同一提交；相同标识不同内容冲突；提交成功但响应丢失能查询并确认，不盲目重跑模型或业务工具。
- [ ] 在工具意图后、工具结果后和终态前分别中断真实隔离进程：已提交记录保留、未知副作用不自动重发，未来上下文的工具调用与结果仍合法配对。
- [ ] 公开成功终态只能在相应上下文与轮次终态持久化确认后出现；故障界面可解释，不泄露 SQLite/内部 scope/路径等实现细节。
- [ ] 模型、MySQL、Redis 或私有网络失败均不会通过清空历史或自动创建空会话掩盖；Redis 失效不能丢失已提交会话。
- [ ] 真实开发者工具完成一次中断后的业务追问；保留故障前、故障说明与新一轮结果截图，禁止执行生产控制或创建生产任务。

## Execution contract

只在既有隔离业务 worktree 推进，沿公开入口做红→绿行为回归和真实进程验烟；不修改原 Runtime，不向生产写控制、任务、通知或配置。未完成的检查保持未验收，不能写假回退或占位实现。每个闭环保留对应实现、回归、说明与语义提交；最终才做一次审查。不启动子代理。
