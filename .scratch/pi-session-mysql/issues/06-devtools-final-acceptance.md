## Acceptance criteria

- [ ] 01–05实际完成；S01–S08的官方契约、迁移校验和故障注入通过，无跳过或缩窄测试换绿。
- [ ] 在真实账号、真实模型、真实授权只读上游下完成验收表 U01–U06/O01/O02；每条证据来自实际界面，包含必要的发送前、重启/切换后和业务结果截图。
- [ ] Office/Company追问、恢复草案重核、任务确认单不创建、真实报告引用及管理恢复均关联原事实，不注入 token、消息、卡片、样本数据或伪造成功。
- [ ] 同一最终构建和来源标识贯穿截图、迁移记录与工程结果；旧失败截图独立保留，不覆盖或改作成功。
- [ ] 已有业务缺陷保持公开未验收/阻塞，不因持久化迁移关闭原业务票；这些路径可纳入原约20条灵活代表样本，不另凑20条。
- [ ] 全部实现和真实验证完成后，仅做一次最终 Standards/Spec 审查并处理实质问题；按用户要求不启动子代理、不开展中途反复审查。
- [ ] 交付报告明确已通过、未通过、环境限制、回滚/恢复策略和客户测试入口；若任何必要结果未达成，不能声称完备或把验证责任静默转给用户。

## Execution contract

只在既有隔离业务 worktree 推进，沿公开入口做红→绿行为回归和真实进程验烟；不修改原 Runtime，不向生产写控制、任务、通知或配置。未完成的检查保持未验收，不能写假回退或占位实现。每个闭环保留对应实现、回归、说明与语义提交；最终才做一次审查。不启动子代理。
