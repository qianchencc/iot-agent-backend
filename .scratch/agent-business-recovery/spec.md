# Java 业务完整性恢复与通用 Agent Engine 规格

Status: ready-for-agent
Date: 2026-11-02

本规格及[验收矩阵](acceptance.md)是本轮业务恢复的执行依据。[执行索引](README.md)列出票据、旧票承接和缓存集成边界。用户已确认十六组业务闭环；本规格发布不代表实现或验收完成。

## Problem Statement

客户需要由 Java 团队独立维护、扩展的完整物联 Agent 后端。当前新后端既把工具契约、物联提示词和业务事件放在 Node，又存在任务、报告、能耗、引用上下文和前端投影未贯通的问题。已有类、接口、测试、本地 smoke 或 resolved-local 状态没有证明用户能够完成实际业务。

原 Runtime 是用户确认可靠的业务行为基线。需要迁移它的业务语义，而不是要求客户重新描述已有协议、缩小时间/设备范围，或让前端迁就新后端错误的协议。已进行的缓存设计和实现是资产，但读取速度不能代替业务完整性。

## Solution

交付 Java 业务后端与业务无关的 Node Agent Engine。Java 团队能够定义和维护每项业务，不必修改 Node 源码或重新构建其产物；Node 只提供通用 Pi 基础能力。功能实现范围仍以指定说明书为准；按用户最新决定，本轮真实前端验收采用约20条代表案例，不严格卡数量或固定清单，不要求全量通过。实际通过案例提供可追溯截图，直播、回放提供真实动态画面证据。

主验收使用真实账号、真实模型和当前授权的真实只读上游。草案可以不执行、任务可以不创建；执行后展示和管理行为仍需证据，优先使用既有真实历史，必要时使用来源明确的独立本地事实副本。隔离证据注明范围，不能声称证明客户设备已执行。真实执行适配仍必须实现，不以 fixture 或 fail-closed 充当完整能力。

## User Stories

1. 作为客户 Java 维护者，我希望工具用途、参数及业务指引只维护一份，以便增加业务无需修改 Node。
2. 作为维护者，我希望真实新增业务工具可以由同一个 Node 产物执行，以便直接证明职责分离，而不是依靠架构图。
3. 作为维护者，我希望 Agent Engine 只处理通用循环、模型、流、会话与中断，以便 Pi 升级和业务变化互不牵连。
4. 作为维护者，我希望 Java 配置的指引和运行限制实际进入当前 run，以免保存成功但行为不变。
5. 作为使用者，我希望沿原登录和园区体系从首页进入总览及两个 Agent，不需要新增账号体系。
6. 作为使用者，我希望精简和详细总览显示各功能真实数据、准备或失败状态，不以零或空列表冒充已取得数据。
7. 作为办公室用户，我希望“当前位置”“本层”等指代绑定实际关注区域，以免查错设备。
8. 作为用户，我希望按名称、别名和位置查询设备，有歧义时列候选或澄清，不猜测设备。
9. 作为设施管理人员，我希望公司七类设备来自当前公司授权，不能混用办公室或底层超范围目录。
10. 作为用户，我希望控制先显示真实设备、现态、目标和确认入口，未确认不执行。
11. 作为用户，我希望按范围批量操作、排除过道或会议室，预览清单的拟操作、排除和无需操作数量准确。
12. 作为用户，我希望逐台选择、搜索、排除、编辑、取消和恢复草案，过期后只能重新核验。
13. 作为用户，我希望空调电源、温度、模式、风速及同类统一编辑正确，超出允许范围不能提交。
14. 作为用户，我希望门禁同样经过人工确认，模型不能替我执行开门。
15. 作为用户，我希望已下发、实测回读、失败、部分完成和无需操作分别有事实依据。
16. 作为能耗使用者，我希望用电按度和上海计量日边界核算，缺采样如实说明而不是补零。
17. 作为能耗使用者，我希望本月、近30天、近7天、单日、自定义和任意历史期间保持完整能力。
18. 作为能耗使用者，我希望夜间分析真正计算20:00至次日08:00，而不是全天数据换一个标题。
19. 作为能耗使用者，我希望时间比较保持共同可比集合，区域比较保持同一期间和独立范围，必要时按单台平均归一。
20. 作为用户，我希望页面与对话的统计、排序、覆盖和比较结果一致，卡片能看明细并继续追问。
21. 作为报告使用者，我希望服务器根据需求取得和核验事实后生成报告，不保存模型虚构的统计区块。
22. 作为报告使用者，我希望报告可预览、下载PDF、导出表格、重启后重读并沿同一报告追问。
23. 作为安全使用者，我希望分别查询烟感、燃气、水浸及日期区间，一类失败不抹掉其他类，也不冒充完整。
24. 作为安全使用者，我希望从告警详情和引用对话查找关联摄像头，多候选时选择，保留原告警时间窗。
25. 作为视频使用者，我希望对话、设备和台账入口最终播放真实授权直播/录像，返回时释放资源。
26. 作为用户，我希望告警答复给出核实建议，不谎称已通知或已处置。
27. 作为用户，我希望一次性和区间任务先显示时间、范围、动作和阶段，放弃后不创建。
28. 作为用户，我希望每日、工作日、指定周几和月度规则成为真正周期计划，而非只存一条一次性任务。
29. 作为用户，我希望定时报表、当前窗口剩余检查点和下一次发生时间准确，可恢复且不重复执行。
30. 作为用户，我希望条件巡检区分单次和窗口，按15/30/60分钟展开，缺少必要时间或频率时澄清。
31. 作为用户，我希望条件、动作、检查报告和节能估算有服务器依据，不能仅保存任意JSON就声称支持。
32. 作为用户，我希望全部任务、日历、周期安排和办公室区域时间轴呈现同一套真实任务事实。
33. 作为用户，我希望查看阶段、逐设备结果、完整操作记录、报告和异常标记，并能引用追问。
34. 作为用户，我希望暂停、跳过、取消及通知已读改变正确对象，历史执行结果不被改写。
35. 作为用户，我希望同一租户不同账号、Office/Company及不同区域的数据和对话不串用。
36. 作为用户，我希望切换身份后重载当前身份数据，旧请求不能回写新身份页面。
37. 作为用户，我希望引用告警、环境窗口、报告、任务或计划后，后端重新核验并保留原业务上下文。
38. 作为用户，我希望断线重入、失败重试和显式停止有明确语义，既不丢失结果也不重复操作。
39. 作为用户，我希望普通页面读取后端已有结果，准备和更新失败不伪装无数据，手动刷新不被同步上游拖住。
40. 作为运维人员，我希望业务事实、Pi上下文和可重建缓存职责清晰，重启和恢复不丢事实。
41. 作为验收人员，我希望说明书每一条场景和附录指令都有当前构建的操作结果与截图，不用接口或旧截图代替。
42. 作为客户，我希望上游未提供的水表和人员统计被如实标注，而不是制造能力成功或扩大本轮接口建设。

## Implementation Decisions

- Java拥有 Business Agent Definition：按来源和当前授权选择工具，定义名称、参数schema、业务描述、指引及经核验的引用和当前业务上下文。
- 私有Tool Bridge传递有版本的数据定义、通用运行策略、工具调用及结果；不传可执行脚本，不把模型提供的身份或来源当作授权。Java恢复并校验完整run/conversation/turn绑定。
- Node把数据定义适配到Pi，实施通用模型循环、流式输出、超时、取消、会话恢复与压缩。Node不出现物联工具名分支、设备字段schema、业务提示词、业务状态解析或小程序卡片组装。
- Java把工具结果投影为原Runtime公开事件，保持既有前端可观察契约。引擎内部事件不直接充当业务事件；不通过前端兼容层掩盖新后端错误。
- 人工确认由Java的用户操作入口核验；模型可提案，不获得直接确认下发或创建自动化的能力。权限、参数、范围、有效期、版本和幂等是Java强约束，不依赖提示词。
- 保留Java已有目录、能耗、草案、任务、报告、存储和缓存成果；逐闭环对照可靠Runtime修复。底层机制可复用，不按语言行数追求逐字迁移，也不保留obsolete shim。
- MySQL保存Business Fact，Redis保存可重建结果/协调，Pi Session由Node SQLite承载。短时视频地址不落为长期事实。
- 完整实现一次性、区间、周期和条件任务执行链及报告/通知链；禁止只有fixture/fail-closed执行适配。生产禁写与代码完整性是两件事，隔离工程验证不能冒充设备真实生效。
- 普通读取与后台同步分离的缓存规格继续有效。缓存主线单独实施，取得可审查提交后集成；不整包搬入其未提交改动，不重新设计缓存平台。
- 本工作区使用独立运行资源：端口、业务schema、Redis命名空间、Pi Session、Admin状态和事实副本。复制出的本地配置/数据库文件不能作为共享运行资源直接启用。
- 真实只读主链路不注入消息、卡片或模拟响应。执行后场景优先真实历史；隔离事实副本保留来源、脱敏及身份映射，管理变化在生产出口关闭条件下实际操作。
- 逐票完成实现、风险回归、代表前端路径验证、双轴审查及语义提交；票内UI条款是候选步骤，不额外要求全量验收。约20条样本可复用覆盖多票；未抽到或缺资料项公开标为未验收，不用假数据/样片冒充，也不因未抽到就取消业务实现。

## Testing Decisions

用户已确认以下验证面：

1. **Business Acceptance：实际微信前端。** 同一真实账号操作新Java+真实sidecar+真实模型+授权只读上游，跑通约20条代表路径并截图，数量与具体样本可调整；最终同一构建复验所选路径，不要求说明书每条候选案例全过。视频仍须真实时间推进画面，未抽到项保持未验收。
2. **工程回归：现有公开HTTP/NDJSON及包根入口。** 验证口径、范围、授权、错误、状态转换、幂等、过期、断线恢复和重复执行等消费者可观察行为。复用既有协议夹具与契约惯例，不测private方法、SQL/源码字符串、wiring或mock回声。
3. **引擎契约：私有Java/Node协作。** 验证数据定义装载、通用工具回调、上下文绑定、取消、超时、重启和Pi Session，不用它宣称物联业务通过。

每个不确定行为沿一个红→绿切片推进。用户已报告的故障直接作为事实，不为重新证明它而运行检查；修复后验证其原路径。Standards审查与Spec审查分别报告，不用测试数量或66/69路径计数替代说明书验收。正常、缺数、越权、未确认、过期、部分失败及恢复等分支按对应场景落证据。

## Out of Scope

- 修改、重启、部署、压测或切换生产Runtime；为填截图而进行生产控制、任务、通知或配置写入。
- 用Java重写Pi本身、建立第二套登录/账号体系，或接入说明书明确未提供接口的水表/人员统计。
- 反向修改Runtime基线、缩减设备/时间范围、吞错、制造报告或以样片替代真实监控。
- 原缓存工作区未提交内容的整体迁移、共享数据库/运行目录、覆盖用户现有登录态。
- 与说明书业务闭环无关的视觉重设计、泛化插件/缓存/预热平台或客户其他产品模块。
