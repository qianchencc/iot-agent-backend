## 统一结果契约

| 证据 | 对用户呈现 |
| --- | --- |
| 草案权威状态为 EXECUTING | 正在执行，请稍候 |
| 门禁开门一次获得受理回执，无物理回调 | 已下发；不宣称门已打开，不继续轮询门状态 |
| 照明／空调仅受理，未证实目标状态 | 已下发 |

| 上游明确拒绝 | 未受理 |
| 传输中断或结果未知 | 下发结果未知；不自动重发，不声称已下发或安全未下发 |

- `ActionResultProjector` 统一确认响应、草案详情和会话恢复。权威草案 status 始终覆盖旧 result 标签；聚合 message/outcome 从已记录的回执、参数和执行时回读推导，不查询当前状态来重写过去。
- 新结果持久化完整契约；旧历史只在读取时投影，原持久化 JSON 不改写。原 response/error、Runtime 历史 readback/observedStates/observedAt 映射保留。旧 `response.fields` 补为规范字段结果，参数证据优先于粗粒度整机标签。
- confirm 的200／502均返回扁平执行结果；未执行的取消、过期、待确认草案不伪造执行事实。
- 门禁仍现读授权，但不做确认前设备状态查询或下发后状态轮询。空调缺少温度读数不能被 NaN 比较判成达标；缺少确认前状态时也拒绝用旧报告确认本次操作。
- 显式业务拒绝不再变成传输未知；参数部分受理不再变成整台拒绝。任何已受理参数／设备之后发生鉴权失败，都不能回滚成可重试草案。
- 即时操作历史和定时任务同步消费部分受理：没有完整成功设备但已有受理参数时仍记 PARTIAL，而非全失败或完成；参数证据继续进入设备结果。未知历史不再伪装成已下发未回读，门禁历史不声称物理核验。
- 前端仅在权威 EXECUTING 时转圈和锁定输入；总结整理单独轮询。卡片、设备块和详情共用终态语义，缺文案的旧记录也不回退为执行中。
