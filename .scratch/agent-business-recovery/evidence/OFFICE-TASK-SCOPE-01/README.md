日期：2026-11-05。状态：代码、工程回归和固定后端发布完成；真实办公室“两阶段工作日照明确认单”通过提案级验收。未确认创建周期任务，未下发设备控制，未验收现场执行。

## 问题与修正

本轮确认的是业务迁移及契约缺口，不是办公室需要换模型的证据。原 Runtime 的 `expandLightingScope`／`company-control-task` 原则作为只读对照，单向落实到 Java；未改动或运行原 Runtime。

- 当前关注区域、完整规范区域名先绑定已授权区域 ID，不再依赖安装地址的近似命中。只剔除重复区域条件，保留更窄的筛选；关注区域是默认值，不是禁止访问其他已授权区域的权限上限。重名及真正模糊范围仍需查明，标点不做破坏性归一化。
- 整组包含允许完整持有的 `exact` 或授权 `browse`，排除子集只允许 `exact`。未解决范围返回结构化恢复信息，不能靠换候选编号重复撞同一失败。
- 办公室整组照明、候选成员、显式设备与公司目标共用[控制预检](../../../../src/main/java/ltd/qianc/iotagent/task/internal/TaskControlPreflight.java)。跨阶段按唯一设备合并能力／状态读取；能力及绑定不通过仍拒绝，鉴权失败不降级。当前已满足或暂未读到状态的设备仍保留在未来阶段。
- [运行防空转](../../../../src/main/java/ltd/qianc/iotagent/agent/internal/AgentRunGuard.java)识别持久化候选 UUID、模型短句柄和设备短句柄，包括跨轮引用。真正改变精度、完整成员、控制绑定或能力／状态事实可以重新准备；仅换编号、刷新观察时间不算进展。过期引用失败也计数并保持原调用幂等。
- [Node](../../../../agent-sidecar/src/agent.ts)只转发 Java 的不透明错误码和恢复数据，模型可见信息保留完整、有界 JSON；没有新增物联判断或自动重试业务分支。

真实前端复验另外发现：公共预检原只输出计数，办公室路径没有公司路径已有的 `includedScopes`／`excludedScopes`／`excludedCount`，卡片直接读取这些字段时整块渲染为空。已在后端恢复完整范围事实；照明保留纳入／排除来源，显式成员展示已核验设备名。未用前端空值兜底隐藏缺口。
