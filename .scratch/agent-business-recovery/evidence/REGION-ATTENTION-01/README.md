# REGION-ATTENTION-01：区域异常提示对齐

日期：2026-11-04。用户报告“26楼运营办公区有待查看的异常结果，但找不到具体异常”。实现已在固定 Java3381 生效；Node3382、模型、前端地址及其他已交付业务实现保持不变。

## 原因与语义

原 Runtime `apps/runtime/src/tasks/store.ts:469–477` 只在以下条件同时满足时提示：同租户的办公室任务属于 `partial/failed/interrupted/missed`，涉及该授权区域，至少一个阶段设备在当前读取授权内，且任务更新时间严格晚于当前查看者的区域已读水位。没有水位只表示从未查看，不表示存在异常。

迁移后的 `CompanyOfficeObservationAdapter` 错把 `attention = !seen` 当成异常判断；此外普通 `/regions` 的整份 CURRENT 快照会把本地异常和已读结果一起缓存。前者产生首次访问误报，后者延迟消除旧提示及发现新提示。

## 实现

- 区域目录继续通过原有后台读快照获取；`?section=directory` 仍只提供名称，冷目录保留准备态，任务存储不可用不影响目录入口。
- 普通 `/regions` 在持有目录之外，通过 `RegionAttentionReader`、现有 `TaskProjectionStore` 和本地 MySQL 即时投影异常，不缓存任务异常和已读布尔值；响应 `Cache-Control: no-store, private`。
- 授权复用原有 `TaskReadScope` 普通读取入口。HTTP 不同步爬取上游；授权准备中或不可用明确失败，不把未知写成没有异常。
- 已读水位按租户和稳定查看者批量读取，避免逐区域查询；写入继续使用数据库 `GREATEST` 保证单调。
- `/regions/{id}/seen` 对照原 Runtime 现读成员目录及设备授权，已撤销区域404，不使用昨日目录授权写入。
- 异常分类复用任务投影的四态口径，`UNCONFIRMED/DISPATCHED` 不算异常。复用阶段设备解析，不为布尔提示生成完整详情与报告。
- 前端源码未修改；原有“真实时间轴成功并完成视图更新后才标记已读，服务端确认后清除本地提示”的流程保留。

- 定向21项通过；最终 `mvn -q verify` **471项，失败／错误／跳过均为0**。删除3个固化旧错误或仅断言字段默认值的适配器测试，不重新钉死错误行为。
