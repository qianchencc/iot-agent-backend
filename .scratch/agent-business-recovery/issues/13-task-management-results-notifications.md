# 13: 任务管理、结果、通知与审计

**What to build:** 任务中心提供全部任务、日历、周期安排三个视图，办公室端另设按区域时间轴展示的「区域工作台」；任务详情显示执行阶段、逐设备结果、完整操作记录、报告附件与引用追问入口。结果严格区分“平台回读确认”“仅已下发”“部分完成/失败”“无需操作”，失败可查看逐台原因。隔离环境支持暂停、跳过、取消、已读/未读流转；已执行记录不可改写。通知中心由真实的“任务扫描 → 结果/报告 → 通知”实现产生，不得有 noop 环节；打开通知自动标记已读。历史事实来源与导入能力不得被预设存在。

**Blocked by:** [07: 服务端取证的报表、导出与引用](07-evidenced-reports-exports.md)；[11: 周期计划与定时报表](11-recurring-plans-reports.md)；[12: 条件任务与空调巡检](12-conditional-ac-inspections.md)

**Status:** ready-for-agent

## 说明书章节

第 2 章 2.5（逐设备结果语义、查看原因、无需操作、全程留存）；第 3 章 3.4（报表经通知中心查收）；第 5 章 5.5（全部任务/日历/周期安排、办公室区域工作台时间轴、任务详情、取消、引用追问）、5.6（结果进通知中心、打开自动已读、报告长期保存与引用、状态与第 2 章一致）、5.7（暂停/跳过/取消、异常提示、取消不影响已执行结果）。逐条案例见 [验收矩阵](../acceptance.md)，完整规则见 [规格](../spec.md)。

## 本票必须自包含的规则

- 三个任务视图与办公室区域工作台共享同一任务事实：全部任务按日期分组并区分待执行/结果；日历月视图以异常标记（橙点）并可点击日期查看；周期安排显示规则/下次执行/最近结果；区域工作台按区域时间轴显示时间、安排人、执行状态。
- 任务详情必须含执行阶段、逐设备结果、完整操作记录、报告附件与引用入口；报告附件复用 [07](07-evidenced-reports-exports.md) 的持久报表事实，不伪造链接。
- 逐设备结果严格区分：已完成且平台回读（附实测值）、已下发但未回读、部分完成/失败（附逐台原因）、无需操作。不得把“已下发”写成“已完成”，不得用接口成功代替回读。
- 已执行任务记录不可变：暂停/跳过/取消只影响未来执行；取消后已执行结果保留，不能被回滚或删除。
- 暂停/跳过/取消/已读状态在隔离环境验证；操作需权限校验，越权请求明确失败。
- 通知由真实执行后的扫描产生：任务结束或报告生成 → 产生通知事实 → 通知中心可读；打开通知自动标记已读，未读计数一致。禁止用固定假通知、只写日志的 noop 或前端本地状态冒充。
- 异常任务在日历（橙点）、区域标记（黄点）与通知中一致体现，不能三处口径不同。
- 历史事实来源和导入能力不得假设已存在；如需要历史数据，必须提供真实来源与可验证导入，无法提供时记录显式缺口，不生成假历史。
- 本票不在生产暂停/跳过/取消任务、不发送生产通知、不写生产数据；隔离本地实例验证，明确标注本地范围。

## 验收条件

- [ ] 隔离本地实例配合真实前端，任务中心显示全部任务（按日期分组、待执行/结果分列）、日历（月视图、异常橙点、点击日期）、周期安排；同一任务在三处状态一致。
- [ ] 办公室区域工作台按区域与时间轴显示当日任务的时间、安排人与执行状态；区域标记与异常状态一致。
- [ ] 打开任务详情，显示执行阶段、逐设备结果、操作记录、报告附件与引用入口；附件能打开真实报表（复用 [07](07-evidenced-reports-exports.md)）。
- [ ] 选取可追溯真实历史或副本中的已完成/实测回读、已下发、部分完成/失败、无需操作结果，验证真实前端文案和原因；缺某类事实保持未验。人工构造/故障夹具只计工程验证，不制造业务通过截图。
- [ ] 对异常任务点击“查看原因”，显示逐台原因且与操作记录一致；引用追问可携带任务/报告上下文。
- [ ] 隔离环境暂停、跳过、取消分别生效且只影响未来；取消后已执行设备结果与报告仍完整，记录不可修改。
- [ ] 任务结束/报告生成后通知真实产生，通知中心可见；打开后自动已读、未读计数减少；不存在无来源假通知或仅前端标记。
- [ ] 越权访问其他用户/来源的任务、通知、报告时被拒绝或裁剪，不泄露设备与结果。
- [ ] 全程无生产任务操作、生产通知、生产写入；证据含截图、脱敏诊断、隔离环境标识、构建/账号/来源/区域。

## 工程回归与真实前端验收的区别

工程回归可验证任务读取、结果字段、通知事实与不变性；业务完成必须由真实前端三个视图、详情、原因、通知已读证明，不能以接口列表或单测替代。

## 隔离与安全约束

业务修改只在隔离 worktree；原 backend 与 Runtime 只读，必要的真实前端修复另用独立 mp worktree且保持原契约。任务/通知/报告只写隔离环境自有 MySQL；可生成本地站内通知并操作本地已读，不发送生产通知、不操作生产任务、不写生产配置。
