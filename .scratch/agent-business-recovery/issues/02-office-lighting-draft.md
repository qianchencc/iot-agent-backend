# 02: 办公室当前区域照明确认单

**What to build:** 在办公室 Agent 中沿用真实登录态与当前关注区域，用户输入“把当前位置的灯打开”（或等价表述）后，助手检索并读取该区域授权照明，列出真实候选与当前状态，展示非空的照明确认单：逐台目标状态、拟执行与排除台数、已符合目标状态无需操作的台数、按位置分组。支持逐台勾选、搜索、排除、取消、重新核验与有效期；超时显示“核验已过期”并禁止执行，重新核验后生成新草案。确认前不下发任何控制。本票承接原工作树中同名票据的未完成业务目标，但原票据的修复补丁未提交、未进入本分支，不得导入、复制或声称已修复。

## 本票必须自包含的规则

- 关注区域来自真实 Office 运行上下文（principal + source + 当前区域），不得由模型或客户端文本伪造；只有该区域的授权照明进入候选。
- 每个候选必须给出真实设备标识、名称/位置、当前开关状态与目标状态；上游读取失败时明确报错，不以空列表或假设备掩盖。
- 存在候选设备时确认单不得为空：不得出现空“操作范围”或“无法生成控制草案”。台数必须自洽：拟执行 + 排除 + 已符合目标无需操作 = 本次考虑的设备集合。
- 支持逐台勾选、搜索、排除与逐台修改目标；取消草案不产生任何设备指令；重新核验必须重新读取当前状态后替换旧草案。
- 草案有效期由 Java 侧决定并返回；过期后确认入口必须显示“核验已过期”且不能执行，重新核验成功后才可执行。
- 确认与执行是 Java 侧人工授权，不是 LLM 工具；本票验收只到确认单，不确认执行，不触达生产控制。
- 原工作树的空操作范围失败是真实历史；其未提交修复不在本分支。必须从本分支现状重新实现并复验，不得引用旧补丁或旧构建作为通过证据。

## 验收条件

- [ ] 真实授权账号在微信开发者工具办公室页，关注区域为 26 楼运营办公区（或等价真实区域），输入“把当前位置的灯打开”，前端显示该区域真实照明候选、每台当前状态与非空确认单；截图与脱敏事件记录齐全。
- [ ] 确认单显示拟执行台数、排除台数、已符合目标无需操作台数，且数值与设备清单一致；不存在空“操作范围”。
- [ ] 逐台勾选、搜索、排除、逐台修改目标均在前端生效；被排除设备不出现在拟执行集合中。
- [ ] 点击取消后前端无执行结果，服务端无下发记录，设备状态未因本操作改变。
- [ ] 等待草案超过有效期后，确认入口显示“核验已过期”且无法执行；重新核验后获得反映最新状态的新草案，旧草案不可复用。
- [ ] 全程未向真实设备下发控制、未创建任务、未发送通知；确认动作仅停留在草案。
- [ ] 工程回归与真实前端验收分别记录；`OFF-CTL-01` 的旧失败截图只作历史，不构成通过。
