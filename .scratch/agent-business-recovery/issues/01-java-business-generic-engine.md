# 01: Java 业务定义与通用 Node 执行引擎

**What to build:** 一次性原子切换 Agent 的业务边界：所有 IoT 业务定义——工具名称、入参 schema、描述、来源过滤、角色与业务指令、已校验的引用/当前时间/提案上下文、授权、业务计算与执行、业务事实、Runtime 兼容的前端事件投影——全部由 Java 提供；Node 只保留通用 Pi 循环、模型流式、取消与超时、会话与压缩、SDK 适配。以真实 Office 设备查询和一个真实需要的 Java-only 业务扩展证明边界，且 Node 源码与构建不变。Java↔Node 使用版本化纯数据私有契约，禁止代码注入。迁移完成后删除 Node 内旧定义与所有别名/兼容分支，不保留双写或回退开关。

**Blocked by:** None (can start immediately)

**Status:** resolved

## 说明书章节

第 1 章（两个助手入口、适用范围、只显示授权设备）；跨第 2–5 章（检索、控制、能耗、告警、视频、任务都必须走 Java 业务定义）；第 6 章（身份、权限、审计）。逐条可执行案例及本票对应关系见 [验收矩阵](../acceptance.md)，完整规则见 [规格](../spec.md)。

## 本票必须自包含的规则

- Java 拥有全部 IoT 业务定义与判定；Node 源码不得保留 IoT 工具名、schema、来源分支、状态字符串解析、卡片投影或业务提示词。
- Node 拥有通用执行策略（循环、模型流、取消、超时、会话、压缩、SDK 适配）；Java 只描述通用执行策略，不实现第二套 agent loop。
- 私有桥接契约必须版本化、纯数据、可校验；不得允许模型、客户端或配置注入可执行代码；运行上下文（principal、tenant、source、关注区域、当前时间、引用）由 Java 核验并绑定回调身份，Node 不得伪造。
- 人工确认与执行是 Java 侧 UI 授权，不得暴露为 LLM 可调用执行工具。
- 一次性迁移现有 Node 内全部业务定义和事件映射；迁移后不保留别名、兼容字段、双份定义或按开关回退。
- 新增业务能力只改 Java 即可经真实前端使用，Node 目录与构建产物保持不变；该扩展必须是真实需要的能力，不是为演示而造的假工具。
- 数据归属：业务事实 MySQL、可重建缓存 Redis、Pi 会话 Node SQLite；不复用原工作树的 var DB、缓存端点或私有配置。
- HTTP 200、NDJSON 事件终态、单测或构建通过只作诊断，不能替代真实前端业务结果。

## 可追溯 Runtime 业务参考职责

以现成 Runtime 源码、契约和既有证据为业务参考，逐项记录“Runtime 行为 → Java 业务定义/事件投影 → 验收案例”的映射。不得修改 Runtime 以适配新后端，不得测试、切换或重启生产 Runtime；用户已确认原 Runtime 工作正常，新后端未成熟是接受事实，不重复证明失败。原工作树未提交代码、草稿修复和生成物不进入本分支。

## 工程回归与真实前端验收的区别

工程回归只证明外部接口与包根契约未破坏，用于诊断和防回归；业务完成必须由真实小程序前端在真实账号、真实上游、真实模型下观察到的业务结果与截图证明。两类证据分目录保存，不得互相替代。

## 隔离与安全约束

业务修改只在本隔离 worktree；原 backend 与 Runtime 只读。必要的真实前端缺陷/已授权缓存整改须在独立 mp worktree 修复，不为错误后端添加兼容。当前服务和登录不切换；不写生产配置、任务、通知或控制，真实授权只读上游可查询。
