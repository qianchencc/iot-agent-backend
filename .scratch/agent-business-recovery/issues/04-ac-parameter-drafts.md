# 04: 空调参数草案与编辑

**What to build:** 在真实公司 Agent 对话中，用户描述目标空调状态（如“把 26 楼会议室空调开到 24 度制冷”），助手生成包含每台空调的确认草案，逐台给出当前观测状态与拟调整目标；支持长按或等价交互对单台自定义调整电源、模式、风速、温度，也支持对同类设备统一调整。温度目标限制在 16–30℃（含端点），越界时不能提交并给出明确提示；无效参数不下发。草案确认前不执行控制。

**Blocked by:** [03: 公司七类授权目录与照明+空调混合范围](03-company-catalog-mixed-scope.md)

**Status:** ready-for-agent

## 本票必须自包含的规则

- 草案中每台空调必须区分“当前观测值”与“本次目标值”；不得把目标值显示成实测值，也不得把上次缓存值冒充当前状态。
- 可编辑参数为电源、模式、风速、温度；模式与风速取值来自真实设备能力，不提供设备不支持的自由文本值。
- 温度目标同时接受 16 和 30；15 及以下、31 及以上必须在提交前被拒绝并给出可读提示，草案保持可修改，不产生控制请求。
- 同类批量调整与逐台覆盖并存：批量修改影响当前选中的同类设备，逐台修改只影响该台且不被后续批量误覆盖；界面与最终提交集合一致。
- 目标设备必须来自当前授权目录与已澄清的范围；设备不唯一时先候选/追问，不猜测。
- 取消草案不产生控制；草案有效期与“核验已过期”规则与照明确认单一致（见 [02](02-office-lighting-draft.md)）。
- 本票不执行真实控制、不创建任务、不发送通知。

## 验收条件

- [ ] 真实公司账号在前端输入“把 26 楼会议室空调开到 24 度制冷”，草案列出真实空调设备、当前观测状态与目标 24℃/制冷；截图完整。
- [ ] 长按或等价交互可修改单台电源、模式、风速、温度；修改后草案目标值与当前值仍分列显示。
- [ ] 输入温度 15℃ 或 31℃ 时无法提交，前端显示越界提示，服务端无控制请求；16℃ 与 30℃ 可正常保留在草案中。
- [ ] 对多台同类空调统一调整后，逐台再修改其中一台，最终提交集合中该台保留独立值，其余台保持统一值。
- [ ] 输入“关掉 26 楼会议室空调”生成电源关闭草案，目标状态正确且不误改温度/模式。
- [ ] 点击取消后无下发、无执行结果、设备状态未变；草案超时后确认被拒绝，重新核验生成新草案。
- [ ] 全程无生产控制、无任务、无通知；证据含截图、脱敏诊断、账号、来源、区域与构建 ID。
