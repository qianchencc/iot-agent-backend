# 10: 一次性与间隔任务完整实现

**What to build:** 从真实对话到确认单再到可恢复的任务实现：一次性任务（如“明天 18:00 关闭本层照明”）与区间间隔任务（如“今天下午到明早，每隔半小时查看一次机房温度”）都生成含执行阶段、目标设备、时间/间隔与只读检查的确认单；用户可放弃、可中断后恢复确认；人工确认后才建立任务。Java 内实现真实的生产形态执行适配器（阶段推进、执行、恢复、去重），不得只提供 Fixture 或 FailClosed 作为唯一适配器；生产执行不在本票触达，工程验证在隔离环境完成。任务卡片保持原前端契约。

**Blocked by:** [02: 办公室当前区域照明确认单](02-office-lighting-draft.md)

**Status:** ready-for-agent

## 说明书章节

第 2 章 2.4（确认清单、执行/取消）、2.5（结果语义）；第 5 章 5.2（一次性定时任务的确认单、创建/放弃、任务管理取消）、5.7（创建前人工确认、权限范围、暂停/跳过/取消、取消不影响已执行结果）。逐条案例见 [验收矩阵](../acceptance.md)，完整规则见 [规格](../spec.md)。

## 本票必须自包含的规则

- 一次性任务与间隔任务必须校验并展示：阶段划分、目标设备集合、执行时间或区间、间隔、每次执行的只读检查、是否允许写入动作。
- 目标设备只来自当前授权范围；范围歧义先澄清；服务端展开精确成员，模型不自行拼装设备集合。
- 确认单必须可放弃；放弃不创建任务。确认前断开/刷新后可通过恢复流程继续同一草案，不重复生成或静默丢失。
- 人工确认是 Java UI 授权，不是 LLM 工具；未确认不得调度。
- 配置完整时使用由 Java 业务模块组成的真实生产形态执行适配器；Fixture 只用于隔离测试。缺配置/授权时保留明确 fail-closed 拒绝，但不能以该拒绝实现代替完整配置下的真实执行能力。
- 本票不实际触发生产执行；所有执行验证在隔离环境、隔离数据库、只读上游与明确标记的本地任务中完成。
- 隔离执行验证必须覆盖：阶段按序推进、每次执行记录、进程/连接中断后恢复、同一阶段不重复执行、读取失败不误写、任务终态正确。
- 任务卡片的前端字段、事件名与状态语义保持原 Runtime 契约，不为错误后端增加前端兼容 shim；真实前端缺陷可在独立 mp worktree修正。
- 不写生产任务、不发送通知、不触达生产设备控制。

## 验收条件

- [ ] 真实账号在微信开发者工具办公室页输入“明天 18:00 关闭本层照明”，确认单展示执行时间、目标范围与动作；未点击创建前无任务落库；截图完整。
- [ ] 输入“今天下午到明早，每隔半小时查看一次机房温度”，确认单展示区间、半小时间隔与每次只读检查；阶段/检查点数量与服务端展开一致。
- [ ] 点击放弃后前端无任务、服务端无任务事实、无通知；刷新后不会幽灵出现。
- [ ] 确认过程中断开连接/刷新，恢复流程能回到同一待确认草案并保留原目标与时间；不产生重复草案。
- [ ] 在隔离环境（隔离 MySQL、只读上游、无生产权限）确认创建本地任务，观察到阶段按序执行、每阶段有记录；中断后恢复且同一阶段不重复执行、不重复写入。
- [ ] 隔离环境中读取上游失败或权限不足时，任务记录明确失败/跳过，不伪造成功，也不写生产。
- [ ] 任务卡片在前端按原契约显示时间、范围、状态与入口；无前端兼容 shim。
- [ ] 全程未创建生产任务、未发送通知、未执行生产控制；证据含截图、脱敏诊断、隔离环境标识、构建/账号/来源/区域。

## 可追溯 Runtime 业务参考职责

对照 Runtime 的任务确认单、阶段/间隔模型、任务卡片事件、状态语义与取消行为，记录“Runtime 行为 → Java 任务定义/执行适配器 → 前端或隔离执行证据”。Runtime 只读，不修改、不切换生产。

## 工程回归与真实前端验收的区别

工程回归（隔离执行、恢复、去重）证明执行内核正确；真实前端验收证明确认单、放弃、恢复与任务卡片契约。两者都不能替代“生产执行已获批准”，本票明确不执行生产。

## 隔离与安全约束

业务修改只在隔离 worktree；原 backend 与 Runtime 只读，必要的真实前端修复另用独立 mp worktree且保持原契约。隔离环境使用独立 MySQL/配置与只读上游，禁止生产控制出口；不开启生产任务、通知或配置写入。

## 证据要求

证据落在 `.scratch/agent-business-recovery/evidence/<CASE-ID>/`，覆盖 `OFF-TASK-01` 及验收矩阵中的间隔任务案例；含确认单截图、放弃/恢复记录、隔离执行阶段日志（脱敏）、去重与恢复证据、构建/账号/来源/区域。Fixture 结果单独标注，不作为业务通过。

## 本票尚未验收

本票仅发布规格，尚未执行任何验收；隔离执行通过不等于生产任务或真实设备执行已验收。

## 实现备注（TaskExecutionCorrections，2026-11-02）

- 已修复 P1 执行缺陷：受受理未回读不再记为 adjusted；聚合改为按设备结果（verified/satisfied/observed 为成功，unconfirmed/unknown 计未确认），整点仅在全部成功时 COMPLETED，无回读最多 UNCONFIRMED/PARTIAL。
- 已落地每任务每设备持久调温预约（新表 `task_device_dispatch_reservations`，PK(task_id, device_id)）：单设备下发前原子 reserve，逐台现读状态+复核任务可下发性与授权；取消/操作员变更/窗口结束/重启都不会二次调整；让行也记为持久事实，后续检查点不再重试。`TaskSchemaInitializer` 启动时按既有 adjust 模式检查点结果回填预约（保留既有事实；历史 INTERRUPTED 阶段无可回填设备事实，按原阶段级不重放语义处理）。
- 安全读检查点（safety 设备 + alertWindow previous_day/previous_week 或 alertDays，缺省近 7 天至当前）改为经组合 ObservationAdapter（SAFETY_EVENTS）真实台账窗口读取：窗口锚点为计划日北京时间零点（日历窗半开区间），逐台账 smoke/gas/water 分页到游标耗尽或 20 页上限，按本检查点设备过滤并输出 alerts 证据块（总数/分类/覆盖/失败/最近记录）；某类台账失败只影响该子类设备（read_failed），不用当前状态伪造告警，也不因无关类别失败而误伤。
