# 05: 能耗统计与夜间分析

**What to build:** 公司 Agent 提供可追溯的能耗统计：单位为“度”，按上海时区每日 08:00 作为昨日边界；支持任意日期区间与日/周/月粒度，计算夜间 20:00–08:00 用电、部门与位置的用电排名、覆盖表数与数据完整性；所有数值由服务端计算，前端展示数据卡片、图表与可展开明细；多轮追问“最近能耗”→“最近一周”保持既定范围与口径，不擅自扩大或缩小。缺失数据如实显示“—”或“暂不可用”，不以零值或旧数据替代。水表在甲方上游明确缺失，记录为事实性不可用边界，不伪造水耗。

**Blocked by:** [01: Java 业务定义与通用 Node 执行引擎](01-java-business-generic-engine.md)

**Status:** ready-for-agent

## 说明书章节

第 3 章 3.1（度、08:00 边界、上游无水表）、3.2（最近一日、环比、按日查看、构成与占比、数据缺失语义、偏高提示）、3.3（时间对比入口与统计口径）、3.5（对话查询、夜间用电、部门/位置、卡片与图表、可继续追问）。逐条案例见 [验收矩阵](../acceptance.md)，完整规则见 [规格](../spec.md)。

## 本票必须自包含的规则

- 计量单位为“度”；“昨日边界”按 Asia/Shanghai 每日 08:00 切分，跨时区客户端不改变服务端口径。
- 支持任意起止日期和日/周/月粒度；默认展示不得被无根据地缩短（例如把 30 天缩成 7 天）；用户说“最近”时按产品语义解释并在卡片上标明实际区间。
- 夜间定义为 20:00–08:00，与服务端计量日边界组合时必须明确窗口归属；不得把夜间分析偷换为全天分析。
- 部门/位置排名与占比由服务端依据真实目录与样本计算；返回覆盖表数、缺失表和缺失时段，前端可下钻到逐表明细。
- 缺失样本显示“—”/“暂不可用”，不得用 0、上一次值或估算值静默填补；部分覆盖时结果需标注覆盖范围。
- 多轮澄清（如“统计一下最近能耗情况”→“最近一周”）继承上一轮范围/口径并显式确认；不得因追问丢失对象或擅自改口径。
- 水表与人员统计在上游未提供，必须在能力边界中如实说明不可用，不生成假数据或假卡片。
- 缓存完整性增强（外部缓存票据序列中的 cache#48）是后续集成项，不是本票开工前置；本票不得为等待缓存而缩减统计范围或伪造完整率。
- 本票只读，不写生产能耗数据、不创建任务、不发送通知。

## 验收条件

- [ ] 真实公司账号在前端输入“统计一下最近能耗情况”，返回真实区间、度数、逐表构成与占比；图表与明细可展开，数值与脱敏诊断中的服务端计算一致。
- [ ] 继续追问“最近一周”后，卡片区间与统计口径切换为最近一周且保留同一对象（公司/授权范围），无范围丢失或悄悄扩大。
- [ ] 查询任意自定义日期区间和不同粒度，边界按上海 08:00 计量日计算；跨 08:00 的时段归属在结果中可解释。
- [ ] 查询“分析本月公司夜间用电，找出夜间用电较多的部门和位置”，返回 20:00–08:00 的真实排名与覆盖信息，不下结论为全天用电。
- [ ] 选取存在缺失样本的日期，前端明确显示“—”/“暂不可用”和覆盖范围，不显示 0 或旧值；缺失不影响其余表可读。
- [ ] 水表/人员统计相关提问如实说明上游未提供，不产生伪造数据或“成功”卡片。
- [ ] 全程只读，无生产写入、无任务、无通知；证据含截图、脱敏诊断、账号、来源、区域与构建 ID。

对照 Runtime 的能耗数据源、日边界、聚合、夜间窗口、排名、覆盖与卡片结构，记录“Runtime 计算语义 → Java 服务端计算/投影 → 前端证据”。Runtime 只读，不修改、不切换生产；原工作树未提交缓存不作为本票输入。

## 隔离与安全约束

业务修改只在隔离 worktree；原 backend 与 Runtime 只读，必要的真实前端/缓存整改另用独立 mp worktree且保持原契约。只读真实能耗上游，不写生产、不修正计量数据、不创建任务或通知；不使用原工作树 var DB。
