# 02: 范围排除、精确选择与独立阶段目标保持原意

**What to build:** 同一条照明/空调请求包含地点、排除、混合类型或不同阶段时，Java按用户声明分别解析完整目标，交付准确的即时草案或未来任务卡；不扩大精确选择、不忽略排除、不把不同阶段合成一组设备。

**Blocked by:** [01 公司全范围未来任务](01-company-whole-scope-task.md)的目标解析与固定成员契约。

**Status:** ready-for-agent

## 当前问题与对照

[核查F2/F3](../findings.md)确认Java缺少原Runtime的范围目标契约；多阶段、排除和精确选择的行为等价性尚未证明，不能把单例全灯修复扩展为这些分支已完成。对照原Runtime每阶段targets及照明包含/排除集合的实际规则，不依赖模型自行列举大集合。

## 实现约束

- 复用01的Java解析深模块，贯通范围文本/明确排除/selection及每阶段独立targets，不再创建另一套Node解析或逐工具复制规则。
- 范围线索不是最终选择；模糊名称、未识别排除、冲突或范围外排除须给出可行动缺口，不悄悄忽略、不扩大成整层、不以前端勾选替代服务器查明。
- 混合目标合并去重但保持每种动作和排除关系；每阶段独立保存范围、动作、预检和绑定。无interval的原Runtime合法1–2阶段不得被强制压成单阶段；不添加用户未说的终点动作。
- 即时草案可按原规则去除已满足动作，未来任务不得据当前状态删除固定目标。核验不完整时不把局部成功包装成整个请求已准备。
- 业务定义、校验、缺口解释与卡片事件归Java；Node不出现照明/空调或工具名分支。

## 验收条件

- [ ] 消费者行为验证：包含范围减去真实子集，交集设备仅排除一次；空排除、范围外排除、未知排除按原语义拒绝/澄清，不丢限制。
- [ ] 明确selection严格等于所选成员；宽检索、相似候选或历史对象不自动扩展它。Office关注区域与Company来源不能互相替代。
- [ ] 分阶段反例「3分钟后关闭26楼照明，5分钟后关闭27楼空调」保留两个阶段各自范围与动作，不并集控制两次，不补开机或结束动作。
- [ ] 混合即时目标只交付一份完整草案；任何必须范围未解决时，不把已准备的局部卡片称为整条请求完成。
- [ ] 独立开发者工具选择一条有真实授权数据的范围/排除路径，核对卡片包含、保留、明细及阶段，保存截图；可复用同一真实路径覆盖多个不变量，不要求全卡片遍历。
- [ ] 所有现场操作停在草案/任务提案，不确认执行或创建生产任务；隔离回归与真实截图分别记录。
