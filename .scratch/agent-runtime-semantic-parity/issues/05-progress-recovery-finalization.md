# 05: 调用无进展、失败恢复与确定结果收尾保持等价

**What to build:** Agent查询/提案遇到重复错误时能够停止无进展调用，取得新证据后仍可恢复合法动作；已形成确定提案时不再生成冲突结果，收尾保留已有范围、原对象及待确认状态，不让用户重复说清同一目标。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

## 当前问题与不确定性

[核查F4](../findings.md)确认原Runtime有调用前/后守卫及无工具收尾，所查新实现主要是轮次/调用预算和halt，未见完整等价。另一线程正在修改sidecar以迁移会话，当前源码不自动代表运行v5；先冻结实际版本再验证，不把未运行源码的差异当既成部署故障。

## 架构不变量

- Java拥有领域工具分类、提案冲突、可恢复错误、有效新证据以及业务下一步决策；Node只执行通用Pi调用循环、预算、取消、停止和上下文收尾。
- 优先复用现有Tool Bridge与run绑定；不足时扩展有版本的通用策略/决策协议，由Java给出数据，不传业务脚本。Node不能根据照明/能耗/任务工具名或结果字段决定业务行为。
- 通用层可实现稳定调用指纹、计数等机制，领域是否可重试、是否已形成确定提案等由Java声明或返回。策略状态以run为作用域，取消/超时/终态后不能误复用；不借本票重设计Pi Session存储。
- 同参重复失败与有新事实的合法推进不同；按原Runtime规则和当前可配置预算恢复，不用见错即终止或无限重试两种极端。
- 提案形成后，对同批后续冲突调用也实施约束；结束模型回合仍保留已有候选/对象/提案事实，但不得带新业务工具继续扩张。
- 幂等及副作用防重仍由Java业务模块保证，不能把重复模型调用、传输重试或会话恢复变成自动确认/重复控制。

## 验收条件

- [ ] 隔离引擎/公开桥接行为验证同参重复错误达到既有阈值后不继续执行；取得合法新事实或修正参数可继续，而不是整轮永久禁用所有工具。
- [ ] 预算耗尽或无进展进入保留已有事实的无工具收尾；说明未完成目标，不静默回传普通成功，不建议缩小日期/设备范围绕过服务故障。
- [ ] 已有确定提案时同批后续冲突调用不落第二份矛盾Business Fact；旧已知对象的读取和必要结果核实按原规则允许，不误造新提案。
- [ ] 取消/超时、返回丢失、结果未知和重新进入的反例不重放有副作用操作；隔离测试能区分权威未创建与尚未核实，不用假回执冒充生产结果。
- [ ] 至少一条真实前端已遇到的失败/恢复或提案收尾路径留下处理记录与最终界面截图；不故意破坏生产上游来制造故障，不能以纯引擎测试计业务通过。
- [ ] 若改通用协议，迁移全部调用方并验证旧字段/别名没有留作长期双规则；业务prompt和领域分支全部留在Java，新增业务不要求修改Node。
