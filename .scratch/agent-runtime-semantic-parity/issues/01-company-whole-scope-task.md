# 01: 公司全范围未来任务不再缩成样本动作

**What to build:** 用户提出「3分钟后把公司的灯全关了」时，Java解析当前公司授权照明的完整固定成员，生成范围、数量和明细一致的待确认任务；范围无法完整核验则明确失败或澄清，不再接受标题全楼、实际只有两路的提案。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

## 当前问题

[核查F1/F2](../findings.md)已确认：两个候选集保存81+75个成员，提案却只有2条动作。当前工具要求模型列actions，任务模块只核验已列设备权限，没有等价的完整范围目标解析。不是UI折叠，不为重现而再次创建任务。

## 实现约束

- 对照原Runtime公司范围目标语义，在Java Business Agent Definition和任务模块建立全授权/精确选择可区分的目标契约；本票先贯通明确allAuthorized的单阶段照明目标。
- Java从本端当前授权解析全部固定成员，核验来源、身份、总数及控制绑定；模型只声明目标与动作，不逐台抄设备。不得以调大50条上限、默认扩张任何actions、修改标题或prompt劝说作为完整修复。
- 区分完整成员与模型展示窗口，不把complete=false一律放行。集合真实缺失、过期或跨会话/身份时，不得形成静默部分提案。
- 固定成员成为Business Fact，公开事件和现有卡片使用同一事实；未来目标保留当前已满足成员。确认时仍核验既有授权、版本和绑定，不新增执行授权。
- 不自动把历史两路提案扩成全公司；沿既有退役/过期/版本协议要求重新准备和再次人工确认，旧确认权限不得覆盖扩大后的目标。
- 业务schema、prompt、展开与投影全部在Java；本票不改Node领域逻辑，不改Pi会话迁移。

## 验收条件

- [ ] 用消费者回归覆盖大于50个固定成员的全范围提案；保存动作与当前完整授权集合相等，每个设备恰好一次、动作全部关闭；缺一个成员时不能伪装完整。
- [ ] 精确选择两台仍只生成两台，不因本票修复自动扩成全部；不新增跨来源/跨身份成员。
- [ ] 完整范围包含当前已关闭及当前不可读但仍合法授权的未来目标，不套用即时已满足过滤；无法可靠绑定的成员按原Runtime语义拒绝或列明缺口，不静默删除。
- [ ] 独立开发者工具真实账号发送同一句原话，卡片显示完整范围与可展开明细；本案同一快照应为156路，实际目录变化时以当前核验结果和差异说明为准，不硬编码台数。
- [ ] 真实路径止于待确认，未创建任务或下发设备。截图、构建标识、完整成员与动作脱敏集合校验同批记录；测试通过不能代替卡片证据。
- [ ] 旧错误提案不会借新版本修复静默变成更大可执行范围；保留原失败证据。
