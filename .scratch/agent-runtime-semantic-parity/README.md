日期：2026-11-02。状态：规格与6张票已发布，尚未实施。用户要求本轮只做必要记录和可执行票据；禁止启动子代理，不恢复全卡片遍历。

先读[事实核查](findings.md)、[规格](spec.md)及[既有ADR0004](../../docs/adr/0004-java-business-definition-generic-agent-engine.md)。这是[原业务恢复工作](../agent-business-recovery/README.md)的语义缺口收口，不是另起一套Java/Node架构。

## 不变的归属

|职责|唯一归属|
|---|---|
|业务prompt、工具名/schema/描述、来源/引用上下文|Java Business Agent Definition|
|范围、排除、精确选择、完整成员、权限和提案/确认不变量|Java业务模块|
|任务/报告/草案事实、业务恢复与公开事件投影|Java|
|Pi模型/工具循环、流、取消、超时、预算、压缩、通用执行适配|Node Agent Engine|
|通用停止/恢复协议|Java给出领域决策；Node执行通用指令，不识别物联工具名或字段|
|Pi Session持久化|按ADR0005由Java/MySQL管理，另线程实施；Node保留通用会话语义与薄适配|

新增或修改物联业务应允许Node源码与产物保持不变；必要的通用协议首次补齐不等于把业务长期留在Node。

## 已确认问题

全灯任务引用两个候选集，服务端持有81+75=156个照明成员，却只保存2条动作，标题为「全楼照明关闭」。不是UI折叠。模型逐台列举、缺失范围目标契约以及只校验已列设备权限的路径不能保证用户目标完整。prompt压缩与调用守卫差异另有源码证据，尚未量化为「大部分/全部能力出错」。详细边界见[核查记录](findings.md)。

## 执行纪律与停止条件

- 开工先冻结原Runtime提交及Java/Node实际版本，记录脏工作区与运行包差异；不把已变动源码当运行事实。当前已知v11是隔离预览，不是最终全源码构建。
- 每票包含业务定义→服务器规则→Business Fact→现有事件/卡片→代表验证，不拆成「先prompt、再接口、最后等UI」的横向空闭环。
- 实现遵守红绿回归和深模块原则；使用现有公开入口，不为测试暴露内部实现。必要新协议保持通用，迁移全部调用方，不留双规则或兼容层掩盖错误。
- 每张票列出的前端路径均是定向示例与证据要求，不要求把所有卡片重新走一遍。已知失败不可被未抽验标记掩盖；未选择的其他UI分支保持未验收。
- 任务/控制停在提案，不确认现场执行、不创建生产任务、不发送通知。恢复/幂等副作用测试仅在隔离夹具验证，不能冒充真实现场成功。
- 最终只做一次整体Standards/Spec审查，不启动子代理。现有测试数、HTTP成功或卡片存在不是整体完成条件。
