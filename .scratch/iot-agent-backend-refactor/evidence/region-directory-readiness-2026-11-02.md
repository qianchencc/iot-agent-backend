# 53：区域目录独立读取与重开复用

状态：实现及后端验证完成，真实微信页面待用户验收。未启动子代理，未下发设备控制、创建任务或发送通知。

## 根因与修复

- 原REGION_LIST先officeContext加载完整设备范围，再取得区域目录；生成区域名称并不使用设备范围，形成不必要的慢依赖。
- 现在直接读取当前身份的授权区域目录。directory分区不读attention，也不读设备目录；区域设备/状态/控制的范围检查不变。
- directory使用既有HISTORICAL模板和REGION_DIRECTORY快照空间，动态提示使用REGION_ATTENTION与CURRENT模板；两者复用同一份OFFICE_REGION_CATALOG日更新基础目录，避免提示每分钟重新读取区域网关。普通HTTP读取仍只返回backend已有值。
- 前端按会话身份保存纯区域ID/名称与目录时间，不保存attention或设备状态。同上海日重开立即恢复；跨日保留可选名称并后台对齐。换身份立即清理可见旧目录，401/403清除持久缓存；旧请求不得回写。

## 实际红后绿

- backend公共ObservationAdapter：设备目录返回错误、attention读取也不可用时，区域名称仍应返回；修前实际抛device directory不可用，修后返回精确授权目录。
- 删除原先断言“区域列表必须读取完整设备范围两次”的实现耦合用例，不为旧错误行为重新固定测试。
- 前端公共区域生命周期6项：修前5失败，修后6通过，覆盖重开立即可选、上海跨日更新、失败保留、拒绝访问清理、换身份及迟到响应、登录失效清理。
- 补充公共行为回归：先读取名称，再令区域网关失败并更新已读标记；动态提示仍应返回持有的准确名称及新标记。修前实际抛上游不可用，修后通过，完整backend回归再次通过。
