# 后端当前结果读取：缓存整改规格

状态：2026-11-02 用户已授权审查并实施。取代此前把逐请求重读上游范围、5 秒统一过期、缩短 30 天展示作为必要方案的表述。原票据 31–40 的 resolved 只表示设计讨论收敛，不表示能力已经实现。

## 用户要得到的效果

小程序只面对 backend。普通页面查询、子页、手动刷新取得 backend 当前已有结果，不等待 backend 向上游取数。backend 自己同步数据。没有任何已取得结果时，立即、明确返回准备中；不能用空数组、零用量、无任务、无未读伪装准备成功。30 天、月度环比与年度同比能力不缩减。

## 读取与更新分工

- 普通观察 JSON：概览、公司目录、区域/区域设备/现态、环境历史、能耗统计/比较、台账及其只读资料采用已有结果立即返回；后台取得新结果后替换。
- 当前数据默认 60 秒后台更新；相同 key 只允许一个后台工作。完整历史窗口按上海深夜的下一日刷新；含今天/未明确结束日的查询按当前数据。5 秒只可表示个别真实需求的进度，不是所有缓存最大年龄。
- 原始网关读取、分页、权限范围构建、后台任务准备不得进入前台普通读取的等待链。没有快照可以由首次请求登记一次后台准备，但响应不等待工作完成。
- 已有完整结果遇临时更新失败时保留原数据及原取得时间，并表达更新失败；部分/截断结果不能覆盖上次完整结果或伪装完整。首次只有部分结果时可提供其明确缺数事实，但不能缓存成正常完整数据。
- Redis 用于可重建读取快照；跨进程恢复须配合MySQL中的独立凭据代次屏障。MySQL/sidecar SQLite 的 Business Fact 不改作缓存；无MySQL屏障时仅服务内存并后台同步，不冒充Redis可安全恢复。正常干净关闭可恢复；不干净退出保守地重新准备，不承诺崩溃暖恢复。Redis故障不得阻塞普通HTTP或损坏事实。
- 后台活动读取与重试有容量、并发、间隔及关闭生命周期。不同租户、凭据、来源、完整查询条件隔离；key 不存明文 token。
- 管理端不再提供从未实际控制Java缓存的旧Runtime TTL字段；更新这些字段明确拒绝，不用“保存成功”冒充生效。采用本规格的固定模板。

## 认证与设备范围

保留真正身份认证，禁止把未核验 token 当作已登录。已核验凭据在后端复用，过期更新后台执行；首次核验立即给准备状态并在后台完成，明确拒绝时失效并拒绝继续提供旧结果。不能为了构造缓存键去上游重建范围；范围由后台查询取得，数据按该次有效范围裁剪。不得宣称缓存能实时发现尚未同步到的撤权。

控制确认、执行前权限/目标绑定核验、执行回读、Task/Plan 写入/执行事实、会话流、短时视频地址和报告下载不套用普通页面快照。Task/Plan/通知列表仍直接读 MySQL projection；其必要读取范围只取backend已持有授权ID集合，初次缺数TASK_READ_PREPARING/503，后台同步，按用户权限深夜模板更新。不得把每次通知/未读数/任务报告查看变成全目录上游等待；不缓存这些MySQL事实body。控制的结果与后来的显示状态仍分离。

## External Contract

已有成功 JSON 字段保持兼容，附带 `cache` 元数据：status=fresh/stale/preparing/unavailable，refreshing，updatedAt，retryAfterMs；临时后台错误仅提供脱敏 code/message。首次普通读取返回 HTTP 200、status=preparing，不能同时返回让 UI 误当已加载的空业务数据。首次身份核验用 ACCOUNT_IDENTITY_PREPARING/503，任务读取范围初次准备用TASK_READ_PREPARING/503，前端有限重试；不冒充已登录，不误清会话，不伪造零未读数。400/401/403、错误查询仍保留真实错误语义。

前端已有数据先显示，准备状态不覆盖它；首次准备可在可见页面有限重读（至多约180秒）后自动落位，退出/切身份停止旧请求回写。该窗口只用于首次尚未持有结果，不能让已有结果等待更新。手动刷新绕过前端快照，仅请求 backend 当前结果。前端不需要理解上游或管理上游刷新。

## 本次审查必须纠正的实际缺陷

1. Company 完整目录普通查询不复用；设备现态有直接全量目录读取；dashboard 在查缓存前等范围。
2. 凭据核验每个 HTTP 调 account/me，即使业务快照命中仍可能阻塞。
3. 能耗统一流使用固定每日行数猜测页数，失败页被吞成空页且标完整；不规则真实采样可能漏读，不能基于模拟补数节奏建立正确性。
4. 前端准备/失败响应不得缓存 60 秒或删除另一个新请求的好结果。
5. 原 45 号票“采样不足需客户补接口”和“~1s 首屏已解决”结论撤回：当时统一流错误过滤与不完整时序测量不能证明这些结论。
6. 真实长窗口月报发现：适配器提前过滤掉原始分页边界，逐表组合器无法判断窗口已读完而继续扫描无关档案；12秒前台式预算又截断后台准备。内部扫描保留原始边界并在真实起点停止，后台准备与直接操作超时分开。
7. 最后微信走查发现通知块仍在同步取得全量目录后才读取MySQL未读数；不能因为数据最终来自MySQL就宣称前台没有等待链。已将读取范围单独纳入backend已有结果，保留每次直接读取事实与所有公开报告副本的范围裁剪。

## 验证界面（授权范围）

本轮在现有公开 HTTP/ObservationAdapter/AccountPrincipalVerifier、前端 readSnapshot 与实际微信页面验证，不测试 private 方法。可控上游挂起时普通 HTTP 初次应及时 preparing、已有值应及时返回；后台完成后再次读取有真实数据。覆盖临时失败、明确拒绝、身份/来源/查询隔离、迟到请求、Redis 恢复、完整历史/当日刷新、30 天真实逐表数据。毫秒目标是观察基线，不以降功能或吞错误换数字。

本地真实只读与微信页面为业务证据；不控制生产设备，不切换或压测生产 Runtime。每两个实现票据进行一次 Standards/Spec 双轴审查，修完发现后再交付。
