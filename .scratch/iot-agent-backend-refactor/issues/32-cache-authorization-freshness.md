## 重新澄清：范围核验不等于逐请求重建全目录（待确认方案）

- 用户纠正：完整设备范围读取实际可超过 10 秒，不能用个别接口的 0.6–1.3 秒样本代表完整授权链路。原生产记录 `mp/plan/2026-10-26-ac-verification-next-direction.md` 有授权目录 11.7、12.9、22.7 秒的证据。
- 当前代码：Company 普通目录仅在途合并、不复用完成结果；`readCompanyDeviceStates` 还直接调用 `loadCompanyScope`，绕过该复用入口。完整目录包含环境、电表、安全、照明、门禁、监控与空调。
- 应区分三件事：请求身份认证、依据后端已核验范围检查本次访问、向上游同步范围。不能把三件事都解释为每次 HTTP 请求重新扫描全量设备。
- 待确认方向：普通页面与只读查询使用后端已核验范围及数据快照，不等待范围同步；范围同步独立后台执行。沿用户此前权限低频刷新原则制定周期，不用 5 秒到期强制请求等待。
- 没有已核验范围时立即返回准备状态，不能返回未按权限裁剪的租户数据；后台刷新成功后发布新范围版本并淘汰依赖旧版本的结果。已明确收到认证/授权拒绝时停止提供相应旧快照。
- 设备控制的最终权限核验保留，但应只读目标设备所需的授权与绑定，不加载无关业务目录；控制回读与普通页面查询分开。
- 范围指纹由后台同步结果生成，前台只使用后端已持有版本；不能为了计算指纹重新同步上游。新增哈希键不解决全量目录读取慢的问题。
- 本节记录设计纠正，不表示代码已实现，也不承诺已缓存范围能实时感知上游撤权。
