# 31: 说明书案例验收矩阵（唯一验收来源）

**What to build:** 把 `软件说明书.md` 的每条可执行案例落成可重复的端到端用例（同一 `Authorization`/`Tenantcode`/`source`，必要时带 `focusRegionId`），逐条跑到“当前必红”，修成绿，并留下证据（NDJSON + 草稿/任务事实 + 前端截图）。此票取代票据 30 中“软件说明书案例逐项完成”的模糊条目。

**Blocked by:** None

**Status:** in-progress

## 判据

- 每条案例必须给出：请求、可观察结果、失败时的错误码与文案、是否允许触达客户生产写入。
- 只读案例可反复跑；控制/任务/通知类案例**不得**对客户生产上游真实下发，确认一律停在确认单。
- 证据落在 `.scratch/iot-agent-backend-refactor/evidence/<CASE-ID>/`；前端真实业务结果是验收依据，接口及 NDJSON 仅作诊断。不切换或测试生产后端；生产正常以用户已验证结论为准，失败时对照 Runtime 源码修复。
