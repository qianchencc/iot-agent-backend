# 53: 区域名称不得等待完整设备目录

**What to build:** 用户打开Agent或区域选择器时，先显示backend已有的授权区域名称；后台更新、设备目录和异常提示不阻塞选择。前端只认识backend。

**Blocked by:** None
**Status:** ready-for-human

## 已确认问题

- 前端请求 /regions?section=directory，backend仍通过officeContext先加载完整授权设备范围，区域名称根本没有用到该设备范围。
- 目录分区未从异常关注标记读取中分开，仍使用默认CURRENT策略，而不是既定深夜更新模板。
- 前端只保存选中ID，名称仅存进程内30秒；重开丢失名称，必须重新等请求。

## 改进范围

- 公共ObservationAdapter回归：设备目录和异常标记读取失败时，授权区域名称仍正常返回；授权区域自身读取失败不能冒充空列表。
- backend直接读取当前用户授权区域目录，directory不读取attention；该分区使用既有HISTORICAL模板。动态提示复用同一份HISTORICAL基础目录，只独立计算提示，避免每分钟重复回源读取名称。区域设备/状态及确认控制的校验不削弱。
- 前端按会话身份保存区域ID与名称；同一天重开立即恢复，跨上海日先显示旧值再向backend对齐；异常提示独立更新。换身份、拒绝访问及迟到响应不得泄漏旧目录。
- 不启动子代理，不新建缓存平台；真实页面验收继续由用户完成。

## 验收条件

- [x] 区域名称不受设备目录及attention故障阻塞，公共行为红后绿。
- [x] directory使用既有HISTORICAL模板与独立快照空间，动态提示保持CURRENT独立读取。
- [x] 重开/跨日已有区域立即可选，换身份、401/403及迟到响应边界6项回归通过。
- [x] 完整backend回归、前端265项、158文件边界及开发编译通过；3207已更新完整配置新实例，真实授权清单逐项对照一致。
- [ ] 用户在实际开发者工具确认区域选择体验。

证据：[区域目录独立读取与重开复用](../evidence/region-directory-readiness-2026-11-02.md)。
