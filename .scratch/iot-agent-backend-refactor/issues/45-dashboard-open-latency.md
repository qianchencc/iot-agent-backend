# 45: 物联助手首屏打开超过 10s

**Type:** task
**Status:** superseded; acceptance-reopened-in-50
**Blocked by:** 43, 44

## 症状

用户报告：每次打开物联助手页面加载都在 10s 以上。

## 反馈环

`/tmp/mp-dashboard-timing.py`：导航到 `pages/agent/dashboard`，轮询页面 6 个状态块直到不再是「读取中」，输出各块落定时间。修复前稳定变红（10s 内 3–4/6 落定）。

## 审查纠正（2026-11-02）

- 原“每表约61个采样不足以日差分、需要客户提供新接口”结论撤回。统一流适配器错误地把首行电表作为过滤条件；修复后真实30天有30天用量、43/43表采样，证明不是缺接口。
- 原“约1s首屏已稳定解决”结论撤回。脚本含导航/轮询开销，不能通过减去估计RPC时间声称用户可见耗时；后续仍有红状态，必须按50号重验。
- size=500的大页与编解码上限提高是局部修正，不证明非阻塞读取已经实现。
- 原3秒墙钟预算只能截断工作，不能解决完整业务读取；不能将truncated/暂无数据当性能验收完成。
- 后续发现统一流用固定模拟采样密度猜页数、吞失败页为完整的缺陷，归48号修复。
- 真正的整改目标：前端请求返回backend当前持有结果；后台同步再慢也不能成为前台普通读取的等待链。实现与证据归[整改规格](../cache-current-read-spec.md)及47–50号票。
