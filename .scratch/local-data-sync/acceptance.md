# 最终效果与验收地图

状态：规划，全部本轮验收尚未执行；下列是完成标准，不是当前结果。日期：2026-11-06。

## 1. 最终预期效果

| 场景 | 最终行为 | 不代表什么 |
|---|---|---|
| 已同步目录/历史的普通查询 | 从MySQL或Redis及时取得同一口径业务结果，不等待客户数据上游 | 不保证模型首字或整轮在1秒内 |
| Redis不可用/清空 | 已持久基础数据可从MySQL读取并重建缓存 | 不允许绕过本地授权/持久屏障故障 |
| 客户数据上游暂不可用 | 有效身份和本地范围下，已覆盖历史继续可查；旧状态标时间及异常 | 不允许身份未知或明确拒绝仍读旧结果 |
| 首次未覆盖窗口 | 明确准备/覆盖不足，登记同步需求；完成后原入口可读 | 不冒充零、不承诺无限历史首次瞬时 |
| 首次与每日历史同步 | 首次及每天上海深夜全量覆盖合法来源可访问历史，定时启动后跑完；当前数据约60秒同步独立进行 | 不设24个月边界，不新增限时运行窗口或跨夜轮转，不把用户规模判断冒充本次性能实测 |
| 页面与Agent同问 | 同设备集合、区间、单位和缺数解释；调用入口不同不改变结果 | 不要求模型措辞完全一样 |
| 同步中断或午夜停机 | 恢复持久进度和到期工作；无重复计数、无半份目录发布 | 不因页面闲置而取消登记的同步 |
| 上游补数 | 新统计采用修订后数据并有覆盖依据；已发布报告不静默重写 | 不把历史快照改为最新实时值 |
| 草案与任务 | 准备/查看/只读阶段本地化；确认和真实执行安全规则保持 | 本地状态满足目标不等于未来任务无需执行 |
| 视频 | 本地准备目录/关联/窗口，真实开流取得有效地址 | 缓存旧URL不算可播放 |
| 维护诊断 | 可区分采样、同步成功、同步尝试、模型、工具及交付耗时 | 不能把缓存命中或Langfuse完成代替业务终态 |

## 3. 工程验收：必要不变量

全部在独立端口、schema、Redis命名空间、Pi Session和状态目录进行；不删在线Redis、不阻断用户正在使用的上游网络。

| ID | 条件与操作 | 必须观察的结果 |
|---|---|---|
| E01 | 有效本地身份/授权、基础数据已同步；阻断客户数据读取出口 | 所有普通入口能读取已有覆盖；调用计数0；显式身份/控制/开流例外另计 |
| E02 | 独立环境Redis空或不可用 | 本地读取正确；不因缓存miss触发已覆盖数据回源；无事实丢失 |
| E03 | MySQL不可用/授权持久校验不可完成 | 真实不可用或既有允许的安全降级，无回源兜底、无扩大授权 |
| E04 | 两租户/两主体/company与office、不同令牌代次 | 不串读；失效旧缓存不能恢复旧权限；范围不同的可见字段不混用 |
| E05 | 同步目录中间页失败、返回部分或异常空页 | 当前完整目录保持；新范围未发布；真实空目录须有完整成功证据 |
| E06 | 同历史区间重复同步、中途写入后进程中断 | 幂等、无重复样本/计数；数据提交后推进进度；重启能续作 |
| E07 | 页号漂移、日期参数不可靠、采样乱序或缺口 | 既有完整性检测有效，不把最新时间当完整覆盖，不忽略失败页 |
| E08 | 同窗口多消费者/相邻重叠窗口 | 原始样本复用；同范围不并发重复采集；新统计本地组合 |
| E09 | 关闭页面、闲置超过30分钟、正常及非正常重启 | 已持久数据仍在；登记范围/进度不随缓存条目消失；权限约束继续生效 |
| E10 | 午夜停机、恢复时已过夜间计划 | 恢复到期全量校正；同范围不重入，多个错过的启动时刻不堆积成重复全量任务；不以运行超出某个人为夜间时段取消本轮 |
| E11 | 上游临时失败、旧完整结果存在；再测试明确401/403 | 前者保留原值/原时间并注明异常；后者拒绝对应内容/暂停同步，不混淆 |
| E12 | 上游迟到修订、表计回退/倍率与单位异常 | 原统计语义保持；完整/partial/noData/truncated真实；旧报告不被重写 |
| E13 | 准备草案/任务与真正确认执行分别运行 | 准备无普通数据回源；真实动作不消费陈旧显示状态代替安全复核和回读 |
| E14 | 同步凭据失效/合法轮换、停机恢复 | 按G1暂停/重核/恢复，无明文持久凭据、无借其他主体继续采集 |
| E15 | 普通读取新增入口或绕过检测 | 在既有公开接口/架构约束与出口计数中暴露回源；不得靠源码字串测试 |
| E16 | 新库及旧库升级、回滚演练 | 唯一键/幂等/报告/候选/任务事实保留；回退程序不伪称数据库已回退 |

工程实例的确切代码版本、配置版本、数据范围、阻断对象、请求与结果、出口计数和时间必须记录。运行fixtures只证明工程行为，不证明真实上游或设备执行。

## 5. 延迟证据

分别记录冷启动（无本地覆盖）、本地有数据但Redis空、Redis热读、同步失败时旧值、重启后的读取。每条区分：身份核验/前置、Java本地读取/计算、Node模型各回合、Java工具、终态交付、前端可见。

首屏约3秒、常用工具查询约1秒、刷新约2秒沿用为体验方向；它们不包含首次远期补采，不承诺模型整轮达标。达不到时报告实测与瓶颈，不能通过缩窗口、少取设备、吞错、伪空或关闭授权换数字。
