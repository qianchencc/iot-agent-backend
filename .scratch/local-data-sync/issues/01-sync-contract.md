# 01: 同步范围、凭据与数据契约门禁

**What to build:** 形成可以据此实施且不越权的同步契约：明确用谁的合法凭据、同步哪些数据、怎样判断完整、何时恢复或暂停；以最小只读运行证据排除不存在的服务账号、错误分页假设和无限历史维护。此票交付决策和证据，不交付空同步框架。

**Blocked by:** None (can start immediately).
**Status:** ready-for-agent
**Type:** decision
**Execution:** completed（2026-11-06：G1—G4按LDS-20261106闭合；仅决策门禁完成，不代表02—14实现或业务验收完成）

## 背景与约束

用户确认普通读取消费后端数据，约60秒当前更新、首次全量及每天上海深夜全量历史同步；不为性能缩短30天/同比/自定义能力。全量范围是有权访问的全部历史，无24个月边界。Redis不是事实源，缓存闲置不等于取消同步授权。

## 范围

- 列出已实现的全部普通入口和显式外部出口，对应HTTP、Agent、引用、报告、任务、视频准备；现有ObservationOperationEnum之外的IotAdapter/action/task入口也要覆盖。
- 核实已有凭据托管、安全根和轮换能力。不得把任务凭据直接扩权为通用同步身份，不创建或索取工具能查到的配置。
- 按来源/身份范围核实对象ID、来源记录ID、单位、时区、删除/修订标识、分页排序、日期筛选和增量能力；契约不可靠时记录已验证的保守读取办法。
- 首次及夜间全量采用用户最新决定，历史保留与每轮校正分别记覆盖；夜里定时启动后跑完结束，不新增允许运行时段或跨夜轮转。
- 给出本地数据唯一键和授权隔离规则；没证据证明跨主体可共享时保留主体隔离。

## 门禁产物

- G1：登记触发、允许同步主体、合法凭据引用/持久化授权、过期暂停、重新核验恢复、服务重启行为。
- G2：各数据类别唯一标识和完整性规则、来源分页/补数/删除能力、来源字段敏感级别。
- G3：初始覆盖、常用窗口、夜间校正范围与迟到补数承诺；已有历史不自动删除。
- G4：数据新鲜度与授权有效期分开，哪些旧结果可展示、哪些必须失败关闭。
- 对技术事实自行调查；只有无法从工具、代码和客户契约取得的真实业务取舍才集中问用户。所有未决项列为blocked，不能猜值后把本票关闭。

### 可实施契约 LDS-20261106（主代理裁决）

#### G1：登记、核验与凭据

已核验用户首次访问该来源业务时，登记主体/来源全量同步；只接纳由既有身份核验入口建立的主体，不信任请求自行声明的principal。同步独立加密保存原始凭据，采用现有AES-GCM/外置安全根规范，不读写TASK/PLAN托管记录。AAD绑定租户、主体、来源及用途；凭据正文只在Java进程使用，不入日志、Redis或Node。同步调用前必须通过现有核验策略，失败/明确拒绝分别处理；重启从MySQL恢复登记，重新核验后执行。

同主体合法换证后对象身份保持，凭据代次更新；旧代次在途结果不得发布。新凭据必须核验且取得其授权范围后才能使用本地内容，不能因为owner相同沿用更大旧范围。跨主体不共享目录正文；凭据失效暂停，不借他人凭据补采。凭据解密失败或持久授权检查不可用均失败关闭。既有安全根不具备在线轮换协议，本次不宣称具备；根变更须保持旧凭据可解密或重新登记。

#### G2：来源身份、完整性及修订

以下键均再加来源实例、tenant、已核验owner、company/office；凭据代次用于发布和授权约束，不充当永久来源对象ID。

| 数据 | 已有可复用身份规则 | 持久化规则 |
|---|---|---|
| 目录/区域关系 | 设备类型+来源ID；区域来源ID，Office/区域关系以ID连接 | 保存完整批次及独立授权范围。分页未结束/重复ID内容冲突/任一分支失败不发布；能耗、安全、视频授权分别取其专用范围，不从总目录推导额外授权 |
| 当前状态 | 来源设备ID+状态项 | 真实观测时间、质量和同步时间分别保留；未知不补false，迟到观测不覆盖更新观测 |
| 能耗样本 | Java现有meterId+id+readTime；缺id沿现有readTime回退，并单独标记来源ID缺失 | 不使用Runtime旧SQLite中仅meter+time的主键；同刻异ID共存以保留冲突检查。同键重取更新，原始缺数/回退/倍率/夜间语义不改 |
| 环境样本 | Runtime `environment/history.ts:36-52`：id（缺省为时间+deviceCode/site）+recordedAt+deviceCode/site | 时间统一instant，缺设备码仍归站点；同批按基线身份去重，不按时间单列合并。缺省ID来源单独标记，不把合成ID声称为客户真实ID |
| 安全事件 | 台账ledger+eventId+deviceId+occurredAt；外部引用仍ledger+eventId+deviceId | 依旧按扫描顺序定位外部引用；保留alarm/report及已证实字段，不生成处置/恢复状态。详情及关联摄像头仍分别校验安全/视频范围 |
| 平台事实 | 现有任务/计划/会话/报告/审计主键 | 沿现有事务，不同步复制、不因上游补数改写已发布报告 |

来源缺ID时沿现有兼容规则，不以新增客户保证为前置条件。保留可区分的原始来源ID，不把同秒当作唯一；同批同身份出现冲突值不得悄悄冒充多个已确定来源记录，记录冲突质量。参考：Java `EnergyHistoryStore` 合并键、`CompanyEnergyObservationComposerImpl`同刻冲突检查；Runtime `energy/history.ts`、`energy/meter-history-store.ts`、`environment/history.ts`、`safety/events.ts`。Runtime旧持久表丢失原始ID的实现不移植。

小数从原始JSON number/string直接解析BigDecimal，支持现有科学计数法输入，不经double落库。当前源码没有上游scale保证；数据库采用MySQL最大精度DECIMAL(65,30)作为明确存储边界，不伪称来源精度、不静默四舍五入；不能无损表示的值令该批发布失败并保留旧版本。源字段缺失/不可解析沿原有unknown/缺数处理。统计展示和已确认kWh/倍率口径保持，PM单位仍null。

历史全量从无日期筛选的有效来源流读取至协议末页；使用last、总数及页面行数交叉检查已提供的分页信息，不仅凭totalElements或最新采样时间宣布完整。目录完整数组协议与分页协议区分。能耗继续已验证的无筛选流/页边界次序检查，偏移页号不当永久游标；重复页、逆序或预算终止均不能推进完整覆盖。现有同步批次与持久提交点用于恢复，恢复时重新定位边界，不直接信任过期页号。

修订采用同键更新；历史全量缺行不证明删除，沿Runtime既有upsert-only保留历史，不新增自动删除。目录/授权是当前完整视图，只有完整批次成功后才替换；历史保留不授予当前权限。安全/环境缺少修订字段或处置字段不阻塞，保持未知，不声称客户不存在未使用API。协议字段中的设备名称/位置属于主体隔离的运营资料，控制绑定仅服务端使用，源凭据和个人资料不进入证据或测试。

#### G3/G4：调度与可读性

首次全量，当前数据默认约60秒，历史每天上海03:00启动全量（沿Runtime `energy/meter-sync.ts`既有历史触发时刻）。定时启动后跑完，不定义夜间结束时刻、不增加跨夜轮转；错过计划恢复一次到期工作，同范围不重入。用户提供全量最多十来分钟的实际判断，不重新为确认该判断跑扫描。普通查询从本地读，必要登记不等待采集；全量未完成时已覆盖区间可以按原完整性规则使用，未覆盖不得伪空。

G4复用既有身份核验/拒绝规则和持久屏障；数据新鲜度独立于授权。明确拒绝或核验超过有效上限不得返旧正文；普通采集网络失败在有效授权下保留旧观测并标时间。目录获取不作为每次普通查询的远程前置。真实确认/控制/回读/开流仍通过显式外部出口，平台事实写入仍是本地业务事务。
