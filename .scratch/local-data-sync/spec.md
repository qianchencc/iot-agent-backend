# 本地业务数据与独立同步规格

Status: ready-for-agent
Date: 2026-11-06
交付状态：仅完成设计规格与执行地图；未实施数据库迁移、业务切换或部署。此状态表示可按依赖开展工作，不表示每张票均可立即实施。

## Problem Statement

普通查询的等待和可用性仍受客户上游影响。现有 ReadSnapshots 主要是访问驱动的查询结果缓存：冷读和刷新执行调用方 loader，部分 loader 直接读取客户上游；缓存命中不能证明存在持久本地基础数据。HTTP、Agent、引用、任务和报告仍有不同读取路径。

此前约60秒当前更新、上海深夜历史更新、月份原始采样复用、已有值不等待和明确准备状态等原则有效。本次改变它们的数据来源与生命周期，而非推翻业务规则。缓存条目默认闲置30分钟淘汰，不能作为持续同步登记；Redis保留时间也不代表授权有效期。

## Solution

Java 通过独立同步维护可持久查询的本地业务数据。所有普通读取以本地数据及可重建 Redis 缓存为来源；缺数只登记受控、去重的同步需求，不执行或等待上游读取。首次准备仍可能需要时间，但重复读取、重启和缓存丢失不应使已经持久保存的数据重新依赖客户上游。

客户业务数据采集统一归同步。身份信任建立、真实控制的最终授权/绑定与状态复核、下发及执行回读、短期视频开流保留显式外部出口。模型提供商、Langfuse不是客户业务数据同步源，不在“零业务查询回源”的断言中混算。

## User Stories

15. 作为用户，我希望Agent与页面同问同口径，以免两个入口给出不同数字。
16. 作为用户，我希望引用和追问能在本地定位真实对象，以免卡片有数据但追问失败。
17. 作为报告使用者，我希望新报告从本地样本取证，以便上游暂不可用时仍可生成覆盖完整的报告。
18. 作为报告使用者，我希望旧报告保留发布时依据，以免上游补数静默改写历史报告。
19. 作为任务使用者，我希望提案准备、列表、详情和通知不扫描远程目录，以免本地任务也无法查看。
20. 作为任务执行者，我希望只读阶段与普通查询共用本地数据，同时真实动作继续遵守执行安全规则。
21. 作为用户，我希望手动刷新只询问后端当前结果，不触发一次重型上游全量读取。
22. 作为用户，我希望后台更新失败时已有有效数据保持可见，且原采样时间不被伪造更新。
23. 作为用户，我希望未核验身份和明确拒绝不会获得缓存内容，以免跨身份泄漏。
24. 作为维护者，我希望Redis丢失后从MySQL重建结果，不重新采集已经保存的数据。
25. 作为维护者，我希望同步进度在重启后恢复，以免必须等用户再次打开页面。

27. 作为维护者，我希望重复采集不重复计数，以便安全恢复中断批次。
28. 作为维护者，我希望失败和部分分页不替换上一完整目录，以免短暂故障变成设备消失。

## Implementation Decisions

### 1. 权威与模块职责

- MySQL保存上游数据的本地副本、平台 Business Fact、同步范围/进度/覆盖；上游副本表示某时刻取得的观测，不是此刻物理状态的绝对保证。
- Redis仅保存可重建结果和协调状态。未命中从MySQL重建；Redis不可用不丢业务事实；MySQL不可用不得回源伪装正常，也不得绕过持久授权校验。
- 现有任务、会话、Candidate Set、Action Draft、报告和审计事实沿用，禁止复制第二套事实库。同步目录不是候选集，候选快照不是完整基础库。
- 优先复用 IotAdapter、ObservationAdapter、ReportService、TaskFacade 等既有公开入口，内部替换普通读实现。上游适配仅由同步及命名的真实外部出口持有；内部实现不暴露给其他模块或测试。
- Java拥有同步和业务语义；Node保持通用Agent Engine，不持数据库、同步凭据或业务缓存。终态交付/会话清理既有问题是独立缺陷，不用本次读架构掩盖。

### 2. 存储模型与隔离

| 逻辑数据组 | 持久内容 | 更新规则 |
|---|---|---|
| 来源设备目录 | 来源对象ID、类型、名称、位置、有效性、必要能力/绑定元数据 | 完整批次发布；物理控制绑定仅服务端可用 |
| 区域及成员关系 | 区域层级、设备成员、Office关系 | 与来源/主体范围一致发布；名称不代替ID |
| Authorized Device Scope | 已核验主体、来源、对象及读/控制权限、范围版本、核验时间 | 与设备数据分离；明确拒绝停止服务，旧数据不授予新权 |
| 当前状态 | 设备/状态项、实际值/单位、采样时间及质量 | 仅更新更有效的观测；缺失/迟到不伪造当前值 |
| 电表原始历史 | 来源记录、累计示数、时间、必要倍率及边界采样 | 幂等批写；修订可追溯；不只存日合计 |
| 环境样本 | 站点/测点/指标、值、单位、时间、质量 | 保留真实归属，不臆造区域映射 |
| 安全事件及关联 | 来源事件、类型、位置、发生时间、处置状态、关联对象 | 幂等更新当前事件；来源修订可定位 |
| 同步登记与覆盖 | 来源/授权范围、数据类别、需求区间、发布版本、进度、成功/尝试时间、失败摘要 | 数据提交后推进进度；不受缓存闲置淘汰影响 |

- 对象标识包含租户、上游实例/身份域中实际需要的隔离维度、company/office来源及来源对象ID。主体可见内容有差异时保留主体隔离，未证明一致前不跨账号合并正文。
- Token不作永久对象ID、不入明文查询键或证据。用户已允许独立加密托管已核验主体的同步凭据，采用既有治理和加密原则；不得假设存在服务账号或把任务凭据无授权转为全局同步凭据。
- 查询、过滤、关联、排序、统计字段为结构化列；非核心扩展才用JSON。小数采用DECIMAL，精度按真实单位及来源契约确定，不拍脑袋统一截断。
- 全表沿用bigint unsigned id、create_time、update_time、无外键/级联、既有逻辑删除约定；唯一键、软删除与重建语义在迁移评审中一起验证。大整数对前端为字符串。
- 通过既有SchemaMigrations入口升级，禁止模块另建DDL初始化通道。原始历史不新增自动删除任务，正式保留期限须另行明确。

### 3. 同步策略

- 当前数据默认约60秒；历史/低频范围沿用上海深夜模板。它们是调度节奏，不是精确采样延迟保证，不能把所有接口统一5秒过期。
- 同步登记和进度持久；登记范围内、凭据有效的工作不因页面关闭或缓存条目闲置消失。首次核验/普通请求可以登记所需范围，实际采集由独立同步执行。
- 按数据类别和真实授权范围合并工作，不按每种统计问法创建上游扫描。保留受限执行能力，同范围单飞，能耗网关并发上限沿用6；不新建通用队列、调度平台、无限重试或大量线程。
- 2026-11-06用户最新决定：首次同步覆盖该主体/来源有权访问的全部数据及历史；普通查询仍及时返回本地已有结果或覆盖不足，不等待全量采集。历史查询能力不缩减；没有固定24个月上限，也不是按查询月份逐项建立缓存预热任务。
- 历史每天上海深夜定时启动一次全量同步，跑完结束；用户提供的实际规模判断为最多十来分钟，不再要求证明是否会跨夜。深夜是触发时间，不是允许运行的起止时段，不新增到点中止、跨夜轮转机制。失败保持旧数据并记录失败，不能标为全量完成。
- 同步进度不得使用会漂移的页号冒充永久游标；日期筛选、更新游标、来源ID可靠性先核实。能耗继续保留已验证的无筛选流定位、原始分页边界和采样完整性判定。
- 目录/授权分页成功后短事务发布完整批次；半批失败不发布。历史批次幂等提交后推进进度；完整覆盖单独记录，不以最新采样时间证明中间无缺口。
- 停机错过计划后恢复到期工作；中断重放不重复计数、不重复发布范围、不造成真实动作。初始补采、近期续采和历史校正不能相互无限抢占；优先使用既有并发控制解决。

### 4. 新鲜度、失败与权限

- 分别保留观测时间、最近成功同步时间、最近尝试时间、覆盖区间/质量。更新失败保留旧正文和旧观测时间，不把最近尝试伪装成功。
- 已有完整历史可继续计算；当前旧状态只作注明时间的观测，不能作确认控制或真实执行完成证据。缺样不补零、无观测不伪造空设备；部分结果不得替换上次完整发布。
- 当前目录、数据结果均按本地有效授权裁剪；恢复Redis也不能绕过范围代次/拒绝状态。低频同步不承诺即时发现未知撤权，不额外引入复杂权限推送体系。
- 身份核验失败与普通同步网络失败分开。首次未核验不可视为登录；明确401/403不能用旧缓存降级成功；凭据失效后暂停对应同步，不借其他用户凭据继续。
- 控制最终复核、执行回读、开流等例外保留；普通草案准备、任务提案和状态展示不因“与控制有关”就使用真实执行出口。

### 5. 全部业务调用者与外部契约

- HTTP、Agent工具、引用解析、报告取证、只读任务/检查点必须共用本地业务读取。业务端不自行回源，也不把定时只读任务叫作独立数据同步。
- 保持已有HTTP路径、成功字段、NDJSON终态和错误语义。现有cache元数据可保留兼容；数据时间/质量解释与缓存命中状态分开，不为读架构新增无必要的终态。
- 首次普通查询按既有准备协议及时返回，无空业务数据伪装成功；身份和任务范围准备继续保留各自503契约。已有内容不被preparing覆盖，切身份不接收旧请求回写。
- 手动刷新绕过前端缓存，只询问后端当前结果；必要补采可被登记，但响应不等待上游。有限重读与离页停止沿用现有前端行为，不增加永久轮询。
- 平台事实直接读MySQL。已存报告详情/下载采用本地有效范围校验，不为显示正文先远程扫目录；新报告保留计算口径/证据，补数不静默改写旧报告。
- dashboard、区域时间轴/日历、设备时间轴/日历、未读与任务聚合必须分别取本地观测及本地事实，不能靠单个总览缓存遮住底层回源。
- 视频目录、关联候选及回放准备读本地；短时地址/流会话仍通过专门上游动作创建，不将旧URL伪装可播。

### 6. 已确定与实施门禁

首票必须产出可执行契约，并为以下门禁记录证据或明确待用户决定项，禁止未经确认默认成立：

| 门禁 | 必须确定的内容 | 闭合条件 |
|---|---|---|
| G1 同步身份与凭据 | 已有合法凭据来自哪里；何时登记、暂停、轮换、恢复；允许持久托管的范围 | 来源契约与生命周期实证；缺授权时先问用户，不新造服务账号 |
| G2 数据身份及上游能力 | 对象唯一性、不同账号可见字段、分页/增量/删除/补数能力 | 真实契约/源码/脱敏样本支持唯一键与完整性判断 |
| G3 维护覆盖 | 已决定首次及每天夜里全量，范围为合法来源可访问历史 | 保留现有能力；无24个月边界；夜里定时启动而非限时运行，按用户最多十来分钟的规模判断采用简单全量策略 |
| G4 新鲜度与授权期限 | 哪类旧数据可展示、授权有效约束、拒绝和过期处理 | 复用既有安全规则并明确不能承诺的时效；不将TTL当权限 |

门禁未闭不执行依赖它的迁移/发布；地图可以完整，运行前提不能伪造。用户已要求实施，不等于授权生产变更。

## Testing Decisions

- 以既有包根公开工厂/接口及公开HTTP为主测试面，不能导入其他模块internal，也不为测试放宽ArchUnit。
- 每个领域先证明真实行为：合法数据入库后，同一普通读取在阻断客户数据读取出口、Redis不可用时仍给出一致结果。排除初次身份核验等显式例外时必须写清前提。
- 工程夹具覆盖租户/主体/来源隔离、重复采集、分页失败、缺样、完整发布、迟到修订、授权拒绝、中断恢复和错过深夜；不得以空结果、不抛错或源码字符串匹配代替正确性。
- 沿用ReadSnapshots、AgentReadIotAdapter公开工厂、CompanyEnergyObservationComposer、身份缓存、任务生命周期和报告既有行为测试习惯；具体测试位置在实施时从当前源码定位，不复制实现细节断言。
- 每票定向回归后执行受影响检查；交付边界跑完整工程回归并分类已有无关失败，不宣称未运行的套件通过。
- 新功能必须运行真实隔离程序/脚本烟测，不只测试。真实业务通过只认微信开发者工具结果及截图；工程fixture、接口响应、旧截图不能代替。最终约20条代表路径，不要求全量旧149案例，但已发现的本次缺陷不能用抽样跳过。
- 性能拆分身份准备、业务本地读取/计算、模型回合、工具执行、流交付和前端可见。首屏约3秒、普通工具约1秒、刷新约2秒是体验方向，不是首次补采或模型整轮SLA。

## Out of Scope

- 不新增数据库产品、Kafka/CDC、全量预热平台、通用工作流或复杂撤权框架。
- 不修改原Runtime、不依赖它运行、不切换或测试生产Runtime。
- 不重做任务生命周期、业务授权规则、能耗统计口径、模型路由和会话持久化方案。
- 不在真实验收中下发生产控制、创建生产任务、发送通知或写生产配置；只能验证允许的只读/草案路径，动作安全用隔离夹具。
- 不承诺上游零延迟、无限历史首次即时可用、模型推理压缩至1秒、任何缓存命中都可授权。
- 不新增通用管理台或暴露任意SQL/表浏览；运维证据复用既有受控诊断能力。
